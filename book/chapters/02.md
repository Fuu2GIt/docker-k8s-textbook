## この章のゴール

- Ubuntu に [[Docker Engine]] を入れて、hello-world を起動できる
- Windows で、[[WSL2]] と [[Docker Desktop]] を入れる順番を説明できる
- [[dockerグループ]] に自分を加える理由を説明できる

## 前提

第1章の言葉が分かっていれば足ります。[[イメージ]] から [[コンテナ]] を起動する、という関係だけ使います。

Linux は Ubuntu です。管理者のパスワードを知っている必要があります。先頭の `sudo` は、続くコマンドを管理者として実行する、という意味です。パスワードを聞かれたら入力します。入力中の文字は表示されません。

Windows は、Windows 10 の 22H2 以降、または Windows 11 の 23H2 以降を想定します。メモリは 8GB 以上が Docker の要件です。WSL の初回有効化だけ、管理者の PowerShell が要ります。Docker Desktop の利用者向けインストールは、管理者でなくてよい、と公式ページに書いてあります。

## 手を動かす

Linux では Docker Engine を入れます。Windows では WSL2 を用意してから、Docker Desktop を入れます。手順の番号は揃えています。中身は違います。

この Linux の出力は、すでに Docker が入っている Ubuntu で同じコマンドをもう一度実行したものです。初めて入れるときは、取得と展開の行がこの出力より長くなります。最後まで進み、終了すれば成功です。

9. Docker Desktop を、利用者向けに入れます。

先に、公式の [Install Docker Desktop on Windows](https://docs.docker.com/desktop/setup/install/windows-install/) から `Docker Desktop Installer.exe` をダウンロードします。PowerShell のカレントディレクトリを、そのファイルがあるフォルダにしてから、次を実行します。

```powershell
Start-Process 'Docker Desktop Installer.exe' -Wait -ArgumentList 'install', '--user'
```

何をするコマンドか。 実行場所は、PowerShell です。管理者でなくてよい、と公式ページに書いてあります。 `Start-Process` は、プログラムを起動します。 `-Wait` は、そのプログラムが終わるまで待つオプションです。 `-ArgumentList` は、起動先へ渡す引数です。 `install` はインストーラの導入動作です。 `--user` は、利用者向けの導入で、置き場所は `%LOCALAPPDATA%\Programs\DockerDesktop` です。標準のバックエンドは WSL2 です。

期待する出力。

未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。終わったら、スタートメニューから Docker Desktop を起動し、利用条件の画面を確認します。

出力が違うとき。 ファイルが見つからない旨なら、インストーラがあるフォルダではありません。`cd` でそのフォルダへ移ってから、同じコマンドを実行してください。

4. 鍵を置くディレクトリを作ります。

```bash

```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 この `install` は `apt install` ではありません。ファイルやディレクトリを作る GNU のコマンドです。 `sudo` は管理者として実行します。 `-m` は、権限の数字を指定するオプションです。 `0755` は、所有者は読み書きと実行、他の利用者は読みと実行、という意味の指定です。 `-d` は、引数をディレクトリとして作るオプションです。 `/etc/apt/keyrings` は、作る場所です。

5. Docker の公開鍵を保存します。

```bash
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `sudo` は管理者として実行します。 `curl` は、URL の中身を取得します。 `-f` は、HTTP のエラーでは失敗させるオプションです。 `-s` は、進捗を出さないオプションです。 `-S` は、`-s` のときでもエラーは表示するオプションです。 `-L` は、転送先が変わったときに追いかけるオプションです。 `-o` は、標準出力ではなく指定したファイルへ書くオプションです。URL は Docker の Ubuntu 用の公開鍵です。保存先は手順4のディレクトリです。

期待する出力。

何も表示されません。終了ステータスは 0 でした。`-s` を付けているので、成功時は静かです。

出力が違うとき。 `curl: command not found` と出たら、手順3が終わっていません。通信エラーなら、ネットワークを確認して、同じコマンドをもう一度実行してください。

6. 鍵ファイルを、誰でも読めるようにします。

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `sudo` は管理者として実行します。 `chmod` は、ファイルの権限を変えます。 `a+r` は、全員に読み取りを足す指定です。 `a` は全員、`+` は追加、`r` は読み取りです。GNU coreutils 9.4 の `chmod --help` にあるモードの形に合います。最後の引数は、手順5で保存したファイルです。

何も表示されません。終了ステータスは 0 でした。

出力が違うとき。 ファイルが無い旨なら、手順5の保存先と綴りを比べてください。`/etc/apt/keyrings/docker.asc` をそのままコピーします。

7. Docker の配布元を apt に登録します。

## 確認テスト

文章で答えてください。コマンドを新しく実行しなくても答えられます。

:::quiz
Linux で入れる本体と、Windows で入れるアプリは、それぞれ何ですか。
:::answer
Linux では Docker Engine です。Windows では Docker Desktop です。
:::explain
Docker Engine は、Linux 上でコンテナを動かす本体です。Docker Desktop は、Windows では WSL2 を土台にして、その Engine を使えるようにするアプリです。
:::

:::quiz
`groupadd: group 'docker' already exists` と出たとき、次へ進んでよいですか。
:::answer
進んでよいです。グループは既にあります。
:::explain
Docker のパッケージがグループを先に作っていると、この表示になります。終了ステータスは 0 ではありません。それでも、グループが無い失敗とは違います。
:::

:::quiz
WSL2 を使う Windows で、この教科書のファイルはどこに置きますか。
:::answer
WSL2 の Ubuntu のホームに置きます。
:::explain
Windows 側の `C:\Users` は、Ubuntu からは `/mnt/c` 以下です。速度と改行の差を避けるため、作業は Linux 側でします。
:::

## まとめ

- **Docker Engine**: Linux 上でコンテナを動かす本体です。`docker` コマンドは、ここへ頼みごとを送ります。
- **Docker Desktop**: Windows で Docker を使うためのアプリです。標準では WSL2 の上で Engine を動かします。
- **WSL2**: Windows の中で Linux を動かす仕組みです。この教科書の Windows 側の実行場所は、その中の Ubuntu です。
- **dockerグループ**: `docker` コマンドを、sudo なしで実行できるようにする利用者の集まりです。
