## この章のゴール

- イメージが[[レイヤー]]の積み重ねだと、履歴の行を指して説明できる
- 同じイメージに、別の[[タグ]]を付けられる
- [[レジストリ]]から取得するコマンドと、無いタグのエラーを見分けられる

## 前提

第4章のコンテナは消してあります。イメージは残しています。

実行場所は、Ubuntu の端末です。Windows では、[[WSL2]] の Ubuntu です。コマンドは同じです。

[[イメージ]] は、第1章で、コンテナを動かすためのファイルと設定を束ねたもの、と説明しました。この章はその中身の積み方です。

## 手を動かす

1. 手元のイメージを表示します。

```bash
docker image ls
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker image ls` は、手元のイメージの一覧を出します。引数を省略すると、全部を見ます。オプションは付けていません。

期待する出力。

```text
IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
busybox:1.37.0       bdf57e528e45       6.77MB         2.22MB        
hello-world:latest   11a3eb1597e8       25.9kB         9.49kB        
```

終了ステータスは 0 でした。`IMAGE` は、名前とタグがコロンで繋がった表示です。`ID` は、イメージの識別子の先頭です。`DISK USAGE` は、手元で使っている大きさです。`CONTENT SIZE` は、中身の大きさです。この版の一覧は、古い説明にある `CREATED` 列ではありません。ID と大きさの数字は、取得した日で変わってよいです。2つの名前が見えれば成功です。

出力が違うとき。 行が無いときは、第2章と第4章の取得が終わっていません。`docker pull hello-world` と `docker pull busybox:1.37.0` を実行してから、もう一度一覧を見てください。行がもっと多くても、この2つがあれば成功です。

2. hello-world の履歴を表示します。

```bash
docker image history hello-world
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker image history` は、イメージの履歴を表示します。引数の `hello-world` は、イメージの名前です。タグを省略すると `latest` を見ます。オプションは付けていません。公式の説明では、この履歴の行がレイヤーです。レイヤーは、ファイルの追加や変更を一枚にまとめた段です。

期待する出力。

```text
IMAGE          CREATED        CREATED BY                SIZE      COMMENT
11a3eb1597e8   6 months ago   CMD ["/hello"]            0B        buildkit.dockerfile.v0
<missing>      6 months ago   COPY hello / # buildkit   16.4kB    buildkit.dockerfile.v0
```

終了ステータスは 0 でした。下の行が先に作られた段で、`COPY hello /` はファイルを置いた段です。上の行は、起動するコマンドを決めた段で、大きさは 0B です。`<missing>` は、その段に一覧用のIDが付いていないときの表示です。公式の [docker image history](https://docs.docker.com/reference/cli/docker/image/history/) の例にも、この表示が出ます。`CREATED` の「何ヶ月前」は、実行した日によって変わります。

出力が違うとき。 行が1行だけでも、履歴が出ていればイメージはあります。作成コマンドの文が違っても、`hello-world` の履歴であれば成功です。イメージが無い旨なら、手順1から見直してください。

3. busybox の履歴を表示します。

```bash
docker image history busybox:1.37.0
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker image history` は、履歴を表示します。 `busybox:1.37.0` は、名前 `busybox` とタグ `1.37.0` です。オプションは付けていません。

期待する出力。

```text
IMAGE          CREATED       CREATED BY                          SIZE      COMMENT
bdf57e528e45   2 years ago   BusyBox 1.37.0 (glibc), Debian 13   4.55MB    
```

終了ステータスは 0 でした。このイメージの履歴は、この環境では1行でした。hello-world より段が少なく見えます。大きさの数字と時期は、変わってよいです。`IMAGE` が手順1の busybox の ID と同じなら成功です。

出力が違うとき。 行が複数あっても失敗ではありません。タグの指定が違うと、別の中身を見ます。`1.37.0` を付けているか確認してください。

4. 同じタグを、もう一度取得します。

```bash
docker pull busybox:1.37.0
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker pull` は、レジストリからイメージを取得します。この環境のヘルプには、Download an image from a registry と書いてあります。レジストリは、イメージを置いて配る場所です。 `busybox:1.37.0` は、取得する名前とタグです。オプションは付けていません。

期待する出力。

```text
1.37.0: Pulling from library/busybox
Digest: sha256:bdf57e528e45e4433820e045b29b4597825a1c9e38353532d90a01445013f82e
Status: Image is up to date for busybox:1.37.0
docker.io/library/busybox:1.37.0
```

この出力は、2026-10-16 に、既に手元にある状態で実行した結果です。終了ステータスは 0 でした。最後の `docker.io/library/busybox:1.37.0` が、取得先です。`docker.io` は、Docker Hub というレジストリのアドレスです。初めて取得するときは、層ごとの `Pull complete` が間に出ます。`up to date` は、同じものが既にある、という意味です。

出力が違うとき。 `Pull complete` が並んでも成功です。`not found` と出たら、タグの綴りが違います。`1.37.0` をコピーし直してください。名前を解決できない旨なら、ネットワークを確認してください。

5. 同じイメージに、別のタグを付けます。

```bash
docker image tag busybox:1.37.0 textbook-busybox:practice
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker image tag` は、既存のイメージを指す新しいタグを作ります。この環境のヘルプの形は、`docker image tag SOURCE_IMAGE[:TAG] TARGET_IMAGE[:TAG]` です。最初の引数が元、次の引数が新しいタグです。`textbook-busybox` が新しい名前、`practice` がそのタグです。コピーを新しく作るコマンドではありません。オプションは付けていません。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

出力が違うとき。 元のイメージが無い旨なら、手順4が終わっていません。名前を確認して、もう一度実行してください。

6. 新しいタグの ID を表示します。

```bash
docker image ls textbook-busybox:practice
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker image ls` は、一覧を出します。引数があると、その名前だけに絞ります。オプションは付けていません。

期待する出力。

```text
IMAGE                       ID             DISK USAGE   CONTENT SIZE   EXTRA
textbook-busybox:practice   bdf57e528e45       6.77MB         2.22MB        
```

終了ステータスは 0 でした。`ID` の `bdf57e528e45` は、手順1の `busybox:1.37.0` と同じです。タグを増やしても、中身は増えていません。

出力が違うとき。 行が無いときは、手順5の新しい名前が違います。手順5からやり直してください。ID が手順1の busybox と違っていたら、別のイメージにタグを付けています。

7. 元のタグの ID を表示します。

```bash
docker image ls busybox:1.37.0
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker image ls` は、一覧を出します。引数の `busybox:1.37.0` は、元の名前とタグです。オプションは付けていません。

期待する出力。

```text
IMAGE            ID             DISK USAGE   CONTENT SIZE   EXTRA
busybox:1.37.0   bdf57e528e45       6.77MB         2.22MB        
```

終了ステータスは 0 でした。手順6と同じ ID です。2つのラベルが、1つのイメージを指しています。

出力が違うとき。 ID が手順6と違うときは、途中で別の取得が割り込んでいます。手順5からやり直してください。

## 何が起きたか

`docker pull` は、レジストリ `docker.io` にある busybox のタグ `1.37.0` を確認しました。既にあったので、層の再取得はしませんでした。

`docker image history` は、イメージを作った段を下から上へ見ます。hello-world は、ファイルを置く段と、起動コマンドを決める段の2行でした。イメージは、できたあと中身を書き換えません。変えるときは、上に段を足した別のイメージにします。その作り方は、第6章でやります。

`docker image tag` は、同じ ID にラベルを足しただけです。大きさは手順6と手順7で同じでした。

## 壊してみる

存在しないタグを取得して、エラーを読みます。

1. 無いタグを取得します。

```bash
docker pull busybox:this-tag-does-not-exist
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker pull` は、レジストリから取得します。 `busybox:this-tag-does-not-exist` は、名前は実在し、タグだけをわざと無くしています。オプションは付けていません。

期待する出力。

```text
Error response from daemon: failed to resolve reference "docker.io/library/busybox:this-tag-does-not-exist": docker.io/library/busybox:this-tag-does-not-exist: not found
```

終了ステータスは 1 でした。

出力が違うとき。 `up to date` や `Pull complete` と出たら、実在するタグを指定しています。コマンドをコピーし直してください。

`failed to resolve reference` は、その名前をレジストリで見つけられなかった、という意味です。引用符の中が、探した先です。`docker.io/library/busybox` までが置き場と名前、最後の `this-tag-does-not-exist` がタグです。`not found` は、そのタグが無い、という意味です。

## 確認テスト

文章で答えてください。新しいコマンドを実行しなくても答えられます。

:::quiz
hello-world の履歴で、ファイルが増えた段はどちらですか。
:::answer
`COPY hello /` の行です。大きさは 16.4kB でした。
:::explain
上の `CMD ["/hello"]` は 0B で、起動するコマンドの指定です。ファイルを置いたのは下の段です。
:::

:::quiz
`textbook-busybox:practice` を付けたとき、イメージの中身は増えましたか。
:::answer
増えていません。ID が busybox:1.37.0 と同じでした。
:::explain
`docker image tag` は、新しいラベルを同じイメージへ付けるコマンドです。コピーを別の中身としては作りません。
:::

:::quiz
`docker.io/library/busybox:1.37.0` の `docker.io` は何ですか。
:::answer
Docker Hub のレジストリのアドレスです。
:::explain
レジストリは、イメージを置いて配る場所です。`docker pull` は、そこから手元へ持ってきます。
:::

## まとめ

- **レイヤー**: イメージを構成する、ファイルの変更一枚ずつの段です。履歴の1行が、その段に対応します。
- **タグ**: イメージにつけるラベルです。`名前:タグ` の、コロンの右側です。
- **レジストリ**: イメージを置いて配る場所です。標準では Docker Hub の `docker.io` を使います。

## 片付け

練習用のタグだけ外します。`busybox:1.37.0` と `hello-world` は残します。

1. 練習用のタグを外します。

```bash
docker image rm textbook-busybox:practice
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker image rm` は、イメージの指定を消します。引数は、手順5で付けたタグです。オプションは付けていません。同じ ID を指す `busybox:1.37.0` が残っているので、中身自体は消えません。

期待する出力。

```text
Untagged: textbook-busybox:practice
```

終了ステータスは 0 でした。`Deleted` の行は出ていません。別のタグが同じ中身をまだ指しているためです。

出力が違うとき。 `No such image` と出たら、既に外れています。そのままで次の章へ進んでよいです。`Deleted` まで出た場合は、`busybox:1.37.0` も消えています。`docker pull busybox:1.37.0` で戻してください。
