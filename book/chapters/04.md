## この章のゴール

- [[コンテナ名]] を付けて、コンテナを起動できる
- 動いているコンテナと、終わったコンテナを一覧できる
- コンテナを止めて、消せる

## 前提

第3章まで終わっていて、`docker run --rm hello-world` が成功します。

実行場所は、Ubuntu の端末です。Windows では、[[WSL2]] の Ubuntu です。コマンドは同じなので、タブには分けません。この執筆環境は Ubuntu そのものです。

この章の新しい言葉は3つです。[[デタッチ]]、コンテナ名、[[コンテナID]] です。[[イメージ]] と [[コンテナ]] は、第1章の言葉です。

## 手を動かす

最初のコンテナは、その場で最後まで表示します。次のコンテナは、裏で動かし続けます。

1. 名前を付けて、その場で最後まで実行します。

```bash
docker run --name greeting hello-world
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker run` は、イメージからコンテナを作って起動します。この環境のヘルプの形は、`docker run [OPTIONS] IMAGE [COMMAND] [ARG...]` です。 `--name` は、コンテナ名を付けるオプションです。 `greeting` は、自分で付ける名前です。 `hello-world` は、イメージの名前です。中で実行するコマンドは、イメージに入っているものを使います。

期待する出力。

```text
Hello from Docker!
This message shows that your installation appears to be working correctly.

To generate this message, Docker took the following steps:
 1. The Docker client contacted the Docker daemon.
 2. The Docker daemon pulled the "hello-world" image from the Docker Hub.
    (amd64)
 3. The Docker daemon created a new container from that image which runs the
    executable that produces the output you are currently reading.
 4. The Docker daemon streamed that output to the Docker client, which sent it
    to your terminal.

To try something more ambitious, you can run an Ubuntu container with:
 $ docker run -it ubuntu bash

Share images, automate workflows, and more with a free Docker ID:
 https://hub.docker.com/

For more examples and ideas, visit:
 https://docs.docker.com/get-started/
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。イメージは第2章で取得済みなので、取得の行は出ていません。第2章のように `--rm` は付けていません。表示が終わったあとも、コンテナは残ります。

出力が違うとき。 `name is already in use` と出たら、同じ名前が残っています。この章の片付けの `docker rm greeting sleeper` を実行してから、もう一度実行してください。`Cannot connect to the Docker daemon` と出たら、Docker が止まっています。第2章の確認に戻ってください。

2. 今動いているコンテナだけを表示します。

```bash
docker ps
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker ps` は、コンテナの一覧を出します。オプションを付けないときは、動いているものだけです。この環境の `docker ps --help` には、default shows just running と書いてあります。

期待する出力。

```text
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。見出しの1行だけで、`greeting` はいません。処理が終わって、動いていないためです。他の作業でコンテナを動かしていると、その行も出ます。

出力が違うとき。 `greeting` の行が `Up` で残っているときは、hello-world 以外のコンテナを動かしています。名前を確認してください。見出しだけなら、この手順は成功です。

3. 終わったコンテナも含めて表示します。

```bash
docker ps -a
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker ps` は、コンテナの一覧を出します。 `-a` は、動いていないものも含めるオプションです。`--all` と同じです。

期待する出力。

```text
CONTAINER ID   IMAGE         COMMAND    CREATED                  STATUS                              PORTS     NAMES
151bab80367f   hello-world   "/hello"   Less than a second ago   Exited (0) Less than a second ago             greeting
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。`CONTAINER ID` の `151bab80367f` と、`CREATED` の時刻の表現は、実行のたびに変わります。`NAMES` が `greeting` で、`STATUS` が `Exited` なら成功です。括弧の中の `0` は、中のコマンドが成功して終わった、という意味です。

出力が違うとき。 `greeting` が無いときは、手順1の名前が違います。`Up` のままなら、まだ処理が終わっていません。数秒待って、もう一度実行してください。

4. 裏で動き続けるコンテナを起動します。

```bash
docker run --name sleeper --detach busybox:1.37.0 sleep 300
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker run` は、コンテナを作って起動します。 `--name` は、コンテナ名です。 `sleeper` は、その名前です。 `--detach` は、端末を占有せず裏で動かし、コンテナIDを表示するオプションです。この環境のヘルプには、Run container in background and print container ID と書いてあります。 `busybox:1.37.0` は、イメージの名前です。コロンの右側 `1.37.0` は、そのイメージの版の指定です。詳しくは第5章で見ます。 `sleep` は、コンテナの中で実行するコマンドです。 `300` は、その引数で、300秒待つ、という意味です。

期待する出力。

```text
5f68dd9dc551cce4c58b1a2dbd3347638ad30565f7688783f5638d1874a846b5
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。この64文字がコンテナIDです。自分の実行では、別の文字列になります。1行だけ出て、プロンプトがすぐに戻れば成功です。

出力が違うとき。 `Hello from Docker!` のように長い文が出たら、`--detach` が抜けています。`docker stop sleeper` と `docker rm sleeper` を実行してから、コマンドをコピーし直してください。イメージの取得で失敗したら、ネットワークを確認して、もう一度実行してください。

5. 動いているコンテナを表示します。

```bash
docker ps
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 コマンド自体は手順2と同じ `docker ps` です。オプションは付けていません。動いているコンテナだけを見ます。

期待する出力。

```text
CONTAINER ID   IMAGE            COMMAND       CREATED                  STATUS                  PORTS     NAMES
5f68dd9dc551   busybox:1.37.0   "sleep 300"   Less than a second ago   Up Less than a second             sleeper
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。`CONTAINER ID` の `5f68dd9dc551` は、手順4の64文字の先頭12文字です。自分のIDは、手順4の先頭12文字と一致すれば成功です。`STATUS` が `Up` で、`NAMES` が `sleeper` であることも見ます。`greeting` は終わっているので、この一覧には出ません。

出力が違うとき。 見出しだけなら、`sleeper` は既に止まっています。手順4からやり直してください。`Up` の名前が `sleeper` なら、IDが違っても成功です。

6. 裏で動いているコンテナを止めます。

```bash
docker stop sleeper
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker stop` は、動いているコンテナを止めます。引数の `sleeper` は、コンテナ名です。オプションは付けていません。公式の [docker container stop](https://docs.docker.com/reference/cli/docker/container/stop/) では、中のプロセスに SIGTERM を送り、待っても終わらなければ SIGKILL で止めます。Linux コンテナの標準の待ち時間は10秒です。`sleep` は SIGTERM では終わらないので、この実行では待ち時間のあとで止まっています。

期待する出力。

```text
sleeper
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。止めた名前が1行出ます。10秒ほど返ってこないのは、待ち時間のためです。

出力が違うとき。 `No such container` と出たら、名前が違います。`docker ps -a` で `NAMES` を見て、`sleeper` を指定し直してください。すぐに戻っても、`sleeper` と出ていれば成功です。

7. 止めたあとの状態を表示します。

```bash
docker ps -a
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker ps` は一覧です。 `-a` は、終わったコンテナも含めます。

期待する出力。

```text
CONTAINER ID   IMAGE            COMMAND       CREATED          STATUS                                PORTS     NAMES
5f68dd9dc551   busybox:1.37.0   "sleep 300"   11 seconds ago   Exited (137) Less than a second ago             sleeper
151bab80367f   hello-world      "/hello"      11 seconds ago   Exited (0) 10 seconds ago                       greeting
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。ID、時刻の表現、行の順は変わってよいです。`sleeper` が `Exited (137)`、`greeting` が `Exited (0)` なら成功です。括弧の中は、中のコマンドが終わった番号です。`137` は、この実行で `sleep` が強制停止されたときに付いた番号です。

出力が違うとき。 `sleeper` がまだ `Up` なら、手順6が別の名前を止めています。`docker stop sleeper` をもう一度実行してください。行が増えていても、この2つの名前があれば成功です。

## 何が起きたか

## 壊してみる

存在しない名前を止めて、エラーの読み方を見ます。

1. 存在しないコンテナを止めます。

```bash
docker stop textbook-no-such-container
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker stop` は、コンテナを止めます。 `textbook-no-such-container` は、わざと作っていないコンテナ名です。オプションは付けていません。

期待する出力。

```text
Error response from daemon: No such container: textbook-no-such-container
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 1 でした。

出力が違うとき。 名前が1行だけ出て終了ステータスが 0 なら、同じ名前のコンテナが本当にあります。この章で作った名前は `greeting` と `sleeper` だけです。それ以外を止めた場合は、自分で起動したものか確認してください。

`Error response from daemon` は、Docker Engine が頼みを拒否した、という意味です。`No such container` は、その名前のコンテナが無い、という意味です。コロンの右が、指定した名前です。

## 確認テスト

文章で答えてください。新しいコマンドを実行しなくても答えられます。

:::quiz
`docker ps` に `greeting` が出なくて、`docker ps -a` には出るのはなぜですか。
:::answer
処理が終わって、動いていないからです。`-a` は終わったコンテナも表示します。
:::explain
オプション無しの `docker ps` は、動いているコンテナだけです。`--rm` を付けていないので、終わってもコンテナは残ります。
:::

:::quiz
手順4で表示された64文字と、`docker ps` の CONTAINER ID は、どういう関係ですか。
:::answer
一覧の CONTAINER ID は、64文字の先頭12文字です。
:::explain
64文字がコンテナIDです。一覧は短く切って表示します。この執筆環境では、`5f68dd9dc551` が先頭12文字でした。自分の値は、手順4の先頭と一致すれば同じ関係です。
:::

:::quiz
`docker stop` は、コンテナを消しますか。
:::answer
消しません。止めます。
:::explain
止めたあとも `docker ps -a` に `Exited` で残ります。消すのは `docker rm` です。
:::

## まとめ

- **デタッチ**: コンテナを裏で動かし、端末へはコンテナIDだけを返す起動の仕方です。
- **コンテナ名**: `--name` で自分が見分けのために付ける名前です。
- **コンテナID**: Docker がコンテナに付ける識別子です。一覧では先頭の12文字だけが表示されます。

## 片付け

この章で残した2つのコンテナを消します。イメージは残します。

1. 終わったコンテナを消します。

```bash
docker rm greeting sleeper
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリはどこでも動きます。 `docker rm` は、コンテナを消します。 `greeting` と `sleeper` は、消すコンテナ名です。オプションは付けていません。動いているコンテナは、この指定では消えません。先に `docker stop` が必要です。

期待する出力。

```text
greeting
sleeper
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。消した名前が、1行ずつ出ます。

出力が違うとき。 `is running` と出たら、まだ動いています。`docker stop sleeper` を実行してから、もう一度消してください。`No such container` なら、その名前は既にありません。残っている方だけを指定して消してください。

2. 何も残っていないことを見ます。

```bash
docker ps -a
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker ps` は一覧です。 `-a` は、終わったコンテナも含めます。

期待する出力。

```text
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。見出しだけなら、この章のコンテナは消えています。他の目的で起動したコンテナが残っていれば、その行は出てよいです。`greeting` と `sleeper` が無ければ成功です。

出力が違うとき。 2つの名前が残っていたら、手順1が終わっていません。`docker rm greeting sleeper` をもう一度実行してください。
