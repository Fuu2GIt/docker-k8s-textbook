## この章のゴール

- Web アプリとデータベースを、[[Compose]] の1コマンドで起動できる

2. アプリのファイルを作ります。

```bash
cat > app.py <<'EOF'
import os
import time
from http.server import BaseHTTPRequestHandler, HTTPServer

import psycopg


def connect():
    last_error = None
    for _ in range(30):
        try:
            return psycopg.connect(
                host=os.environ["PGHOST"],
                port=os.environ.get("PGPORT", "5432"),
                user=os.environ["PGUSER"],
                password=os.environ["PGPASSWORD"],
                dbname=os.environ["PGDATABASE"],
            )
        except psycopg.OperationalError as error:
            last_error = error
            time.sleep(1)
    raise last_error


def prepare(connection):
    connection.execute(
        "CREATE TABLE IF NOT EXISTS memos (id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, body text NOT NULL)"
    )
    connection.commit()


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        with self.server.connection.cursor() as cursor:
            cursor.execute("SELECT id, body FROM memos ORDER BY id")
            rows = cursor.fetchall()
        lines = [f"{row[0]} {row[1]}" for row in rows]
        text = "\n".join(lines)
        if text:
            text += "\n"
        body = text.encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_POST(self):
        length = int(self.headers.get("Content-Length", "0"))
        text = self.rfile.read(length).decode("utf-8").strip()
        if text == "":
            self.send_error(400, "empty")
            return
        with self.server.connection.cursor() as cursor:
            cursor.execute(
                "INSERT INTO memos (body) VALUES (%s)",
                (text,),
            )
        self.server.connection.commit()
        message = "saved\n".encode("utf-8")
        self.send_response(201)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(message)))
        self.end_headers()
        self.wfile.write(message)


class MemoServer(HTTPServer):
    def __init__(self, address, handler):
        super().__init__(address, handler)
        self.connection = connect()
        prepare(self.connection)


def main():
    port = int(os.environ.get("PORT", "8000"))
    server = MemoServer(("0.0.0.0", port), Handler)
    print(f"listening on {port}", flush=True)
    server.serve_forever()


if __name__ == "__main__":
    main()
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは `$HOME/docker-learn/ch09` です。 `cat` と `>` と `<<'EOF'` は、第6章と同じ、ファイルを作る書き方です。中身は、メモを PostgreSQL に保存する小さなサーバです。同じファイルを `samples/ch09/app.py` に置いてあります。

`psycopg.connect` は、データベースへ接続します。接続先は、[[環境変数]] から読みます。環境変数は、プログラムの外から渡す名前付きの値です。 `OperationalError` のときは、1秒待って最大30回やり直します。公式の Compose の説明では、`depends_on` は相手が動き始めるまでしか待たず、接続を受け付ける準備完了までは待ちません。データベースの起動が遅いときのためのやり直しです。 `prepare` は、`memos` という表が無ければ作ります。 `do_GET` は、保存済みのメモを行にして返します。 `do_POST` は、送られた文字を1件追加します。 `%s` は、文字を SQL の文へ安全に渡すための印です。文字を SQL の文へ直接つなぎません。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で、同じ内容のファイルを置いて実行しました。終了ステータスは 0 です。

出力が違うとき。 Python のコードが画面に出たら、`>` が抜けています。`cat` から `EOF` までコピーし直してください。

5. Compose のファイルを作ります。

```bash
cat > compose.yaml <<'EOF'
services:
  web:
    build: .
    ports:
      - "8000:8000"
    environment:
      PGHOST: db
      PGPORT: "5432"
      PGUSER: memo
      PGPASSWORD: memo-pass
      PGDATABASE: memo
    depends_on:
      - db
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: memo
      POSTGRES_PASSWORD: memo-pass
      POSTGRES_DB: memo
    volumes:
      - memo-db:/var/lib/postgresql/data
volumes:
  memo-db:
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `compose.yaml` は、Compose が標準で読むファイル名の一つです。この実行では、この名前をカレントディレクトリに置いて `docker compose` が読みました。

`services` の下の `web` と `db` が、サービスです。サービスは、Compose の中の1種類のコンテナです。 `build: .` は、同じディレクトリの Dockerfile からイメージを作ります。 `ports` の `"8000:8000"` は、第7章の `--publish 8000:8000` と同じつなぎ方です。 `environment` は、コンテナへ渡す環境変数です。 `PGHOST: db` の `db` は、データベースサービスの名前です。Compose は、サービス名で届くネットワークを作ります。 `depends_on` は、`web` より先に `db` を起動する指定です。準備完了までは待ちません。 `image: postgres:16-alpine` は、データベースのイメージです。 `volumes` の `memo-db` は、第8章で見た名前付きボリュームです。データベースのファイルを、コンテナの外に残します。

出力が違うとき。 `port is already allocated` と出たら、8000 番が使用中です。第7章のコンテナが残っていないか、`docker ps` で見て止めてください。`app.py` が無い旨なら、カレントディレクトリが `ch09` ではありません。`pwd` で確認してください。

7. サービス一覧を見ます。

```bash
docker compose ps
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker compose ps` は、このプロジェクトのコンテナを表示します。オプションは付けていません。

期待する出力。


出力が違うとき。 `web` が `Restarting` なら、データベースへ繋がっていません。`docker compose logs web` で理由を見てください。30秒待っても `listening on 8000` が出ないときは、`compose.yaml` の `PGHOST` が `db` であることを確認してください。

8. メモを1件保存します。

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `curl` は、URL へ要求を送ります。 `-s` は進捗を出さないオプションです。 `-S` は、`-s` でもエラーは表示するオプションです。 `-D -` は、ヘッダを画面へ出します。第7章と同じ使い方です。 `-X` は、HTTP のメソッドを指定するオプションです。この環境のヘルプには、Specify request method to use とあります。 `POST` は、データを送るメソッドです。 `--data` は、送る本文です。ヘルプには、HTTP POST data とあります。 `'朝のメモ'` が、保存する文字です。URL は、公開した 8000 番です。

期待する出力。

```text
HTTP/1.0 201 Created
Server: BaseHTTP/0.6 Python/3.12.15
Date: Fri, 16 Oct 2026 17:58:24 GMT
Content-Type: text/plain; charset=utf-8
Content-Length: 6

saved
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。`Date` は実行した時刻です。`201` は、新しく作った、という番号です。最後の `saved` は、アプリが返した文字です。

出力が違うとき。 接続できない旨なら、手順7の矢印がありません。`web` のログに `listening on 8000` が出るまで待って、もう一度実行してください。`400` なら、送る文字が空です。`'朝のメモ'` を付けてください。

9. 保存したメモを表示します。

```bash
curl -sS http://127.0.0.1:8000/
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `curl -sS` は、進捗なしで中身を取得し、エラーは表示します。メソッドは指定していないので、GET です。アプリは、表の行を `番号 本文` の形で返します。

期待する出力。


出力が違うとき。 空なら、手順8が成功していません。`saved` を確認してから、もう一度このコマンドを実行してください。行が2行以上なら、同じコマンドを繰り返しています。失敗ではありません。

## 何が起きたか

手順8の POST は、表へ1行追加しました。手順9の GET は、その行を読みました。データベースの `5432` 番は、自分のパソコンへは公開していません。外から話すのは、アプリの 8000 番だけです。

## 壊してみる

Compose のファイルの形を壊して、エラーの位置を読みます。

1. 壊れたファイルを作り、設定の確認をします。

```bash
printf '%s\n' 'services' > broken.yaml && docker compose -f broken.yaml config
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは `$HOME/docker-learn/ch09` です。 `printf` は、`services` という1行だけを `broken.yaml` へ書きます。この行は、YAML として閉じていません。 `&&` の右の `docker compose config` は、起動せずに設定を表示します。 `-f` は、読むファイルを指定します。この実行では `broken.yaml` を読みました。

期待する出力。

```text
yaml: construct errors: line 1: cannot construct !!str `services` into cli.named
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 1 でした。`printf` 自体は成功し、Compose が失敗しています。画面には Compose のエラーだけが出ました。

出力が違うとき。 サービスの一覧が出たら、正しい `compose.yaml` を読んでいます。`-f broken.yaml` が付いているか確認してください。

`line 1` は、ファイルの1行目が原因だ、という意味です。`services` という文字列だけでは、Compose の設定の形になりません。正しいファイルは、`services:` のようにコロンがあり、その下にサービスの中身があります。

## 確認テスト

文章で答えてください。新しいコマンドを実行しなくても答えられます。

:::quiz
`PGHOST` の値を `db` にしたのは、なぜですか。
:::answer
データベースサービスの名前が、ネットワークの中の宛先になるからです。
:::explain
Compose はサービス名で届くネットワークを作ります。`web` から見ると、データベースは `db` という名前です。
:::

:::quiz
`depends_on` は、データベースが接続を受け付けるまで待ちますか。
:::answer
待ちません。動き始めるまでです。
:::explain
公式の説明では、準備完了までは待ちません。この章のアプリは、接続を1秒ずつ最大30回やり直します。
:::

:::quiz
データベースの 5432 番を、自分のパソコンへ公開していないのは、一覧のどこで分かりますか。
:::answer
`db` の PORTS が `5432/tcp` だけで、矢印が無いところです。
:::explain
矢印があるのは `web` の 8000 番だけです。外からメモを話す相手は、アプリです。
:::

## まとめ

- **Compose**: 複数のコンテナの構成を1つのファイルに書き、まとめて起動する仕組みです。
- **サービス**: Compose のファイルの中の、1種類のコンテナです。名前が、ネットワークの宛先になります。
- **環境変数**: プログラムの外から渡す、名前付きの値です。接続先やパスワードを、コードに直接書きません。
