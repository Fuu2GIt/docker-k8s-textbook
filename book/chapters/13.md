## 確認したバージョン

2026-10-16 に、次を確認しました。

- [Pods](https://kubernetes.io/docs/concepts/workloads/pods/)
- このクラスタの `kubectl explain pod.spec.containers.imagePullPolicy`
- `kubectl options` の `--context` と `-n`
- `kubectl apply --help`、`kubectl get --help`、`kubectl wait --help`、`kubectl logs --help`、`kubectl delete --help`
- kind v0.33.0 の `kind load docker-image --help`

クラスタは、第12章で作った `memo` です。コンテキストは `kind-memo` です。

## この章のゴール

- 自作のイメージを、kind のノードへ載せることができる
- [[マニフェスト]] から [[Pod]] を1つ作り、Running になるまで待てる
- [[名前空間]] の中だけを見て、作った Pod を消すことができる

## 前提

第6章のイメージの作り方と、第12章のクラスタを使います。クラスタ名は `memo` です。`kubectl` には、毎回 `--context kind-memo` を付けます。

実行場所は、Ubuntu の端末です。Windows では、[[WSL2]] の Ubuntu です。この章のコマンドは、どちらも同じです。

[[ラベル]] は、リソースに付ける名前と値の印です。あとから、その印で選びます。この章では `app: memo` を付けます。

机の上に、アプリの入った箱を1つ置きます。その机が Pod です。部屋の名前が名前空間です。机の置き方を書いた紙が、マニフェストです。

## 壊してみる

同じ Pod を、create でもう一度作ります。

1. 既存の定義で create します。

```bash

```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `kubectl create` は、新しく作ります。すでに同じ名前があると、apply と違い、エラーで止まります。 `-f` は、ファイル名です。

期待する出力。

```text

```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 1 でした。パスの `/home/ubuntu` は、この環境のホームです。自分のホーム名に変わります。 `AlreadyExists` と `pods "memo" already exists` が出てください。

出力が違うとき。 `pod/memo created` と出たら、先に Pod を消しています。手順8からやり直してください。

`AlreadyExists` は、同じ名前が既にある、という意味です。Pod は、消えるまでその名前を占有します。

:::answer
作って管理できる計算の最小単位です。
:::explain

:::answer

:::quiz

:::explain
名前空間を指定しない get は、今の名前空間だけを見ます。この Pod の metadata.namespace は memo です。
:::

## まとめ

- **Pod**: Kubernetes で作って管理できる、計算の最小単位です。1つ以上のコンテナが、同じノードで動きます。
- **名前空間**: リソースの名前を分ける部屋です。この章の Pod は `memo` に入っています。
- **マニフェスト**: 望ましい状態を YAML で書いたファイルです。`kubectl apply -f` が、それをクラスタへ反映します。
- **ラベル**: リソースに付ける、名前と値の印です。この章では `app: memo` です。
