## この章のゴール

- [[マルチステージビルド]] で、途中の大きなファイルを最終のイメージに入れずに作ることができる
- コンテナを、[[非rootユーザー]] で動かすことができる
- 1段だけのイメージと、複数段のイメージの大きさを比べることができる

## 前提

第6章の [[Dockerfile]] と [[ビルド]]、第5章のイメージ一覧を使います。公開と `curl` は、第7章と同じです。

実行場所は、Ubuntu の端末です。Windows では、[[WSL2]] の Ubuntu です。この章のコマンドは、どちらも同じです。タブは付けません。

作業ディレクトリは `$HOME/docker-learn/ch10` です。

root は、番号が 0 の利用者です。制限なくファイルを変更できます。この章では、アプリを root 以外で動かします。

3. 1段だけの Dockerfile を作ります。

```bash
cat > Dockerfile.single <<'EOF'
FROM python:3.12-slim
WORKDIR /app
COPY app.py /app/app.py
RUN dd if=/dev/urandom of=/app/junk.bin bs=1048576 count=20
EXPOSE 8000
CMD ["python", "app.py"]
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは `$HOME/docker-learn/ch10` です。このファイルは、最終のイメージに大きなファイルを残す例です。同じファイルを `samples/ch10/Dockerfile.single` に置いてあります。

`FROM python:3.12-slim` は、[[ベースイメージ]] を決めます。 `WORKDIR /app` は、作業ディレクトリを作り、そこへ移します。 `COPY app.py /app/app.py` は、ビルドの材料から app.py をコピーします。 `EXPOSE 8000` は、待っているポートのメモです。公開はしません。 `CMD ["python", "app.py"]` は、コンテナの起動時に実行するコマンドです。

`RUN` の `dd` は、ファイルをコピーするコマンドです。このイメージの外で確認した GNU coreutils 9.4 の `dd --help` では、次の意味です。 `if` は、読むファイルです。 `/dev/urandom` は、内容が毎回違うバイト列を出す Linux のファイルです。 `of` は、書くファイルです。 `bs` は、1回に読み書きするバイト数です。 `1048576` は、1024×1024 で、1 MiB です。 `count` は、その塊を何個コピーするかです。 `20` なので、20 MiB です。このファイルはアプリが使いません。大きさが残る様子を見るために、わざと作ります。

出力が違うとき。 Dockerfile の中身が画面に出たら、`>` が抜けています。コマンドをコピーし直してください。

6. 複数段の Dockerfile を作ります。

```bash
cat > Dockerfile <<'EOF'
FROM python:3.12-slim AS build
WORKDIR /src
COPY app.py /src/app.py
RUN dd if=/dev/urandom of=/src/junk.bin bs=1048576 count=20

FROM python:3.12-slim
RUN groupadd --gid 10001 app && useradd --uid 10001 --gid 10001 --create-home --shell /usr/sbin/nologin app
WORKDIR /app
COPY --from=build /src/app.py /app/app.py
USER app
EXPOSE 8000
CMD ["python", "app.py"]
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは `$HOME/docker-learn/ch10` です。同じファイルを `samples/ch10/Dockerfile` に置いてあります。

1つ目の `FROM python:3.12-slim AS build` は、[[ビルドステージ]] を始め、名前を `build` にします。公式の [Dockerfile reference](https://docs.docker.com/reference/dockerfile/) では、FROM は `AS name` でステージに名前を付けられます。その名前は、後の `COPY --from` から参照します。このステージの `RUN dd` は、手順3と同じ 20 MiB のファイルを `/src/junk.bin` に作ります。

2つ目の `FROM python:3.12-slim` は、新しいステージを始めます。公式の [Multi-stage builds](https://docs.docker.com/build/building/multi-stage/) では、FROM は前のステージで作った状態を消して、新しい土台から始めます。ここが最終のイメージになります。

`groupadd --gid 10001 app` は、このイメージの中で確認した `groupadd --help` の `--gid` で、グループ ID 10001 のグループ `app` を作ります。 `useradd` は、利用者を作ります。同じイメージの中の `useradd --help` では、`--uid` が利用者番号、`--gid` が主グループ、`--create-home` がホームディレクトリの作成、`--shell` がログイン用のプログラムです。 `/usr/sbin/nologin` は、このイメージに入っているプログラムです。執筆時にそのプログラムだけを実行すると、`This account is currently not available.` と出て、終了ステータスは 1 でした。ログインを拒否します。

`COPY --from=build /src/app.py /app/app.py` は、`build` ステージの `/src/app.py` だけをコピーします。公式の COPY --from では、コピー元のパスは、そのステージのファイルシステムの根から探します。 `junk.bin` は書きません。

`USER app` は、公式の USER の説明では、それ以降の RUN と、実行時の CMD を、その利用者で動かします。ここでの利用者は `app` です。番号は 10001 です。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

出力が違うとき。 Dockerfile の中身が画面に出たら、`>` が抜けています。コマンドをコピーし直してください。

```dockerfile file=samples/ch10/Dockerfile
FROM python:3.12-slim AS build
WORKDIR /src
COPY app.py /src/app.py
RUN dd if=/dev/urandom of=/src/junk.bin bs=1048576 count=20

FROM python:3.12-slim

WORKDIR /app
COPY --from=build /src/app.py /app/app.py
USER app
EXPOSE 8000
CMD ["python", "app.py"]
```

## 壊してみる

root しか書けない場所へ、番号 10001 の利用者で書き込み、エラーを読みます。

1. 壊れた Dockerfile を作ります。

```bash
cat > Dockerfile.bad <<'EOF'
FROM python:3.12-slim
USER 10001
RUN touch /root/denied.txt
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは `$HOME/docker-learn/ch10` です。 `USER 10001` は、公式の USER では、数値の利用者番号でも指定できます。この番号の利用者は、イメージの中にまだ作りません。 `RUN touch /root/denied.txt` は、その番号で `/root/denied.txt` を作ろうとします。同じファイルを `samples/ch10/Dockerfile.bad` に置いてあります。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

出力が違うとき。 Dockerfile の中身が画面に出たら、`>` が抜けています。コマンドをコピーし直してください。

```dockerfile file=samples/ch10/Dockerfile.bad
FROM python:3.12-slim
USER 10001
RUN touch /root/denied.txt
```

2. 壊れた Dockerfile でビルドします。

```bash
docker build --progress=plain -t memo:ch10-bad -f Dockerfile.bad .
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `-t memo:ch10-bad` は、成功したときに付ける名前です。このビルドは成功しないので、その名前のイメージはできません。 `-f Dockerfile.bad` は、手順1のファイルを読みます。

## 確認テスト

文章で答えてください。新しいコマンドを実行しなくても答えられます。

:::quiz
`memo:ch10` の `/app` に `junk.bin` が無いのは、なぜですか。
:::answer
`COPY --from=build` が `app.py` だけをコピーしているからです。
:::explain
20 MiB のファイルは build ステージに残ります。最終の FROM は、新しい土台から始まります。コピーしなかったファイルは、最終のイメージに入りません。
:::

:::quiz
`docker run --rm memo:ch10 id` が `uid=10001(app)` になるのは、なぜですか。
:::answer
最終ステージの `USER app` が、実行時のコマンドを利用者 app で動かすからです。
:::explain
app は `useradd --uid 10001` で作った利用者です。1段だけのイメージには USER が無く、`id` は `uid=0(root)` でした。
:::

:::quiz
壊したビルドが `Permission denied` で止まったのは、なぜですか。
:::answer
`USER 10001` のあと、その番号で `/root/denied.txt` を作ろうとしたからです。
:::explain
`/root` へは、番号 10001 からは書けません。エラーの `Dockerfile.bad:3` が、問題の行を指しています。
:::

## まとめ

- **マルチステージビルド**: Dockerfile に FROM を2回以上書き、必要なファイルだけを後のステージへコピーするビルドです。
- **ビルドステージ**: FROM で始まり、次の FROM の手前まで続く、ビルドの1区切りです。
- **非rootユーザー**: root ではない利用者です。コンテナのプロセスは、この利用者の権限で動きます。
