## 確認したバージョン

2026-10-16 に、次を確認しました。

- [Overview](https://kubernetes.io/docs/concepts/overview/)
- [Kubernetes Components](https://kubernetes.io/docs/concepts/overview/components/)
- [docker ps](https://docs.docker.com/reference/cli/docker/container/ls/)
- Docker Engine 29.9.1 の `docker ps --help` と `docker run --help`

この章では、Kubernetes はまだ起動しません。起動は第12章です。

## この章のゴール

- 終わったコンテナを、Docker が自分では起動し直さないことを確認できる
- [[Kubernetes]] が、[[望ましい状態]] へ寄せ続ける仕組みだと説明できる
- [[クラスタ]] が、コントロールプレーンとノードから成ると言える

## 前提

第4章の `docker run`、`docker ps`、`docker rm` を使います。イメージ `busybox:1.37.0` は、第5章で取得済みです。

実行場所は、Ubuntu の端末です。Windows では、[[WSL2]] の Ubuntu です。この章のコマンドは、どちらも同じです。

ノードは、コンテナを動かすコンピュータです。コントロールプレーンは、クラスタ全体の状態を管理する側です。

## たとえ話

飲食店のシフト表を想像してください。

「ホールに2人」と書いてあるのが、望ましい状態です。1人が帰っても、店長は表を見て人を足します。Docker は、頼まれた仕事が終わると、そこで止まります。代わりの人を呼びません。

## 手を動かす

1. 1回だけ表示して終わるコンテナを起動します。

```bash
docker run --name once busybox:1.37.0 echo 1回だけ
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。Windows では、WSL2 の Ubuntu です。 `docker run` は、イメージからコンテナを起動します。 `--name once` は、コンテナ名を `once` にします。 `busybox:1.37.0` は、使うイメージです。 `echo` は、後ろの文字を出して終わるコマンドです。 `1回だけ` は、echo が出す文字です。 `--rm` は付けません。終わったあとも、コンテナの記録を残します。

期待する出力。

```text
1回だけ
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。 `1回だけ` が出てください。

出力が違うとき。 `Unable to find image` のあと、取得が始まれば待ってください。 `Conflict` なら、同じ名前が残っています。片付けの `docker rm once` を実行してからやり直してください。

2. 終わったコンテナが残っていることを見ます。

```bash
docker ps -a --filter name=once
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker ps` は、コンテナの一覧です。 `-a` は、`docker ps --help` では、動いているものだけでなく全部を出します。 `--filter` は、条件で絞ります。公式の説明では、形式は `key=value` です。 `name` は、名前の一部、または全部に一致します。 `name=once` は、名前に `once` を含むコンテナです。

期待する出力。

```text
CONTAINER ID   IMAGE            COMMAND          CREATED                  STATUS                              PORTS     NAMES
0040174a9e48   busybox:1.37.0   "echo 1回だけ"   Less than a second ago   Exited (0) Less than a second ago             once
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。コンテナID、時刻、COMMAND の表示は違ってよいです。NAMES が `once`、STATUS が `Exited (0)` であることは一致させてください。

新しい行は出ません。Docker は、終わったコンテナの代わりを作りません。

出力が違うとき。 行が無いなら、手順1が失敗しています。手順1からやり直してください。 `Up` のままなら、すぐ終わるコマンドではありません。`echo` までコピーし直してください。

## 何が起きたか

[[Kubernetes]] は、コンテナで動くアプリを、宣言した状態へ寄せ続けるための仕組みです。宣言は、手順ではなく、こうあってほしいという結果を書くことです。

公式の概要では、Kubernetes は独立した制御を組み合わせ、今の状態を、渡された望ましい状態へ動かし続けます。公式のコンポーネントの説明では、クラスタはコントロールプレーンと、1台以上のノードから成ります。

## 壊してみる

同じ名前で、もう一度起動します。

1. 同じ名前でもう一度起動します。

```bash
docker run --name once busybox:1.37.0 echo もう一度
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。手順1と同じです。コンテナ名 `once` は、終わったコンテナがまだ使っています。

期待する出力。

```text
docker: Error response from daemon: Conflict. The container name "/once" is already in use by container "0040174a9e4838797a30adf38ba7e44c837e389b929f7a2843b83fcd00f4f6a4". You have to remove (or rename) that container to be able to reuse that name.

Run 'docker run --help' for more information
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 125 でした。コンテナIDは違ってよいです。 `Conflict` と `already in use` が出てください。

出力が違うとき。 `もう一度` とだけ出たら、先にコンテナを消しています。手順1からやり直してください。

`Conflict` は、名前の衝突です。 `already in use` は、その名前が使われている、という意味です。終わっていても、`docker rm` するまで名前は残ります。Docker は、空いた名前へ新しいコンテナを自動では入れません。

## 確認テスト

文章で答えてください。新しいコマンドを実行しなくても答えられます。

:::quiz
`docker ps -a` で `Exited (0)` のあと、もう1行コンテナが増えなかったのは、なぜですか。
:::answer
Docker は、終わったコンテナの代わりを作らないからです。
:::explain
`echo` は表示して終わります。望ましい台数を書く場所は、このコマンドにはありません。
:::

:::quiz
Kubernetes が寄せ続ける先は、何ですか。
:::answer
望ましい状態です。
:::explain
公式の概要では、今の状態を、渡された望ましい状態へ動かし続けます。手順を1本ずつ書くこととは違います。
:::

:::quiz
クラスタは、何と何から成りますか。
:::answer
コントロールプレーンと、1台以上のノードです。
:::explain
公式のコンポーネントの説明では、コントロールプレーンが全体の状態を管理し、ノードが Pod を動かします。Pod は第13章で作ります。
:::

## まとめ

- **Kubernetes**: コンテナで動くアプリを、宣言した望ましい状態へ寄せ続ける仕組みです。
- **クラスタ**: コントロールプレーンと、1台以上のノードをまとめたものです。
- **望ましい状態**: こうあってほしい、と書いた結果です。今の状態が違えば、Kubernetes がそこへ寄せます。

## 片付け

1. 終わったコンテナを消します。

```bash
docker rm once
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker rm` は、止まっているコンテナを消します。引数はコンテナ名 `once` です。

期待する出力。

```text
once
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

出力が違うとき。 `No such container` なら、すでに消えています。次へ進んでください。

2. 消えたことを確認します。

```bash
docker ps -a --filter name=once
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。手順2と同じ一覧です。名前に `once` を含むコンテナが残っていないかを見ます。

期待する出力。

```text
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。見出しだけです。

出力が違うとき。 `once` の行が残るなら、手順1が別の名前を消しています。`docker rm once` をやり直してください。
