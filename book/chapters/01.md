## この章のゴール

- [[コンテナ]]と[[仮想マシン]]の違いを、図を指しながら説明できる
- [[イメージ]]が何かを、一文で説明できる
- 失敗したコマンドの1行目から、拒否されたオプションを読み取れる

## 前提

前の章はありません。

新しい言葉は、この章で説明します。Linux の知識は要りません。

用意するものは、端末を開けるコンピュータだけです。Windows では PowerShell を開きます。Linux では Ubuntu の端末を開きます。

## 手を動かす

今のコンピュータが何かを表示します。コンテナは、このコンピュータのOSを借りて動きます。仮想マシンは、別のOSを動かします。まず、借りることになる側を見てください。

[[カーネル]]は、OSの中心で、アプリとコンピュータ本体の仲立ちをする部分です。

:::windows
実行場所は、PowerShell です。スタートメニューで「PowerShell」と検索して開きます。コマンドプロンプトではありません。

`Get-ComputerInfo` は Windows 専用で、Windows PowerShell 5.1 で入っています。

1. Windows の製品名を表示します。

```powershell
Get-ComputerInfo -Property WindowsProductName
```

何をするコマンドか。 `Get-ComputerInfo` は、コンピュータとOSの情報をまとめて出します。 `-Property` は、表示する項目の名前を指定するオプションです。 `WindowsProductName` は項目の名前で、Windows の製品名を指します。Microsoft Learn の [ComputerInfo クラス](https://learn.microsoft.com/en-us/dotnet/api/microsoft.powershell.commands.computerinfo?view=powershellsdk-7.4.0) に、そう書いてあります。

期待する出力。

未確認。この教科書を書いた環境は Linux で、PowerShell を実行できませんでした。

出力が違うとき。 コマンドが見つからない旨の表示が出たら、PowerShell ではなく、コマンドプロンプトか Ubuntu の端末で実行しています。スタートメニューから PowerShell を開き直してください。項目名の綴りが違う旨の表示が出たら、`WindowsProductName` をそのままコピーしてください。

2. OSの版の番号を表示します。

```powershell
Get-ComputerInfo -Property OsVersion
```

何をするコマンドか。 コマンド自体は手順1と同じ `Get-ComputerInfo` です。 `-Property` は、表示する項目の名前を指定するオプションです。 `OsVersion` は項目の名前で、OSの版の番号を指します。ComputerInfo クラスの説明は「Version number of the operating system」です。

期待する出力。

未確認。この教科書を書いた環境は Linux で、PowerShell を実行できませんでした。

出力が違うとき。 番号が手順1の製品名と別の形でも、失敗ではありません。製品名と版の番号は、別の項目です。コマンドが見つからない旨の表示が出たら、手順1と同じく PowerShell で実行してください。
:::

:::linux
実行場所は、Ubuntu の端末です。

1. カーネルの名前を表示します。

```bash
uname -s
```

何をするコマンドか。 `uname` は、今のマシンの情報を表示します。 `-s` は、カーネルの名前だけを出すオプションです。GNU coreutils 9.4 の `uname --help` では、`-s` と `--kernel-name` は同じ意味です。オプションを二つ重ねているのではありません。

期待する出力。

```text
Linux
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。

出力が違うとき。 コマンドが見つからない旨の表示が出たら、Ubuntu の端末ではありません。WSL2 の Ubuntu、または Linux の端末を開いてください。`Darwin` と出たら macOS です。この教科書の Linux 側は Ubuntu で確認しています。

2. カーネルの版を表示します。

```bash
uname -r
```

何をするコマンドか。 `uname` は、今のマシンの情報を表示します。 `-r` は、カーネルのリリースを出すオプションです。`--help` では、`-r` と `--kernel-release` は同じ意味です。

期待する出力。

```text
6.12.94+
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。

出力が違うとき。 数字が違っても、失敗ではありません。カーネルの版は、パソコンごとに違います。英字や数字が1行で出ていれば、この手順は成功です。コマンドが見つからない旨の表示が出たら、手順1と同じく Ubuntu の端末で実行してください。
:::

## 何が起きたか

手順1と手順2は、Docker を動かしていません。今のOSの名前と版を、画面に出しただけです。

コンテナは、このOSのカーネルを借ります。仮想マシンは、別のカーネルを持つ別のOSを動かします。Docker Docs の [What is a container?](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-a-container/) でも、仮想マシンは自分のカーネルを持ち、コンテナは同じカーネルを共有する、と説明されています。

イメージは、コンテナを動かすためのファイルと設定を、一つに束ねたものです。まだ起動していません。起動した実体がコンテナです。イメージの中身が層になっている話は、第5章で見ます。

## 壊してみる

存在しないオプションを渡して、エラーの1行目の読み方を覚えます。失敗させてください。

:::windows
実行場所は、PowerShell です。

1. 存在しないオプションを渡します。

```powershell
Get-ComputerInfo -NotARealOption
```

何をするコマンドか。 `Get-ComputerInfo` は、コンピュータとOSの情報を出します。 `-NotARealOption` は、わざと存在しないオプションです。Microsoft Learn の [Get-ComputerInfo](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-computerinfo?view=powershell-7.4) のパラメーター一覧に、この名前はありません。

期待する出力。

未確認。この環境では PowerShell を実行できませんでした。成功する出力を想像して、ここに書くことはしません。

出力が違うとき。 情報が普通に表示されたら、オプションの綴りが通ってしまっています。`-NotARealOption` を、ハイフンからそのままコピーしてください。コマンドが見つからない旨なら、PowerShell ではありません。
:::

:::linux
実行場所は、Ubuntu の端末です。

1. 存在しないオプションを渡します。

```bash
uname --not-a-real-option
```

何をするコマンドか。 `uname` は、今のマシンの情報を表示します。 `--not-a-real-option` は、わざと存在しない長いオプションです。`--help` の一覧に、この名前はありません。

期待する出力。

```text
uname: unrecognized option '--not-a-real-option'
Try 'uname --help' for more information.
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 1 でした。成功のときのように、画面へ情報の1行だけが出るわけではありません。

出力が違うとき。 `Linux` とだけ出たら、オプションを付け忘れています。コマンドが見つからない旨なら、Ubuntu の端末ではありません。文言が少し違っても、1行目に `uname` と、入力したオプションが含まれていれば、同じ種類の失敗です。
:::

Linux で確認できたメッセージは、こう読みます。

1行目のコロンの左は、失敗したコマンドの名前です。ここでは `uname` です。右側は、理由です。`unrecognized option` は、そのオプションを知らない、という意味です。引用符の中が、今入力したものです。

2行目は、次に試すコマンドの案内です。`--help` を付けると、使えるオプションの一覧が出ます。

## 確認テスト

文章で答えてください。コマンドを実行しなくても答えられます。

:::quiz
コンテナは、仮想マシンと比べて、何を新しく作りませんか。
:::answer
アプリのために、別のOSを新しく作りません。
:::explain
仮想マシンは、別のカーネルを持つ別のOSを動かします。コンテナは、今動いているカーネルを借りて、必要なファイルと一緒にアプリを動かします。
:::

:::quiz
イメージとコンテナは、どう違いますか。
:::answer
イメージは、動かすためのファイルと設定を束ねたものです。コンテナは、それを起動した実体です。
:::explain
イメージは、まだ動いていません。第4章で `docker run` を使うと、イメージからコンテナが起動します。
:::

:::quiz
`uname: unrecognized option '--not-a-real-option'` の1行目から、何が分かりますか。
:::answer
`uname` が、`--not-a-real-option` を知らないオプションとして拒否した、と分かります。
:::explain
コロンの左がコマンド名です。右側の理由に、入力したオプションが引用されています。この読み方は、Docker のエラーでも使います。
:::

## まとめ

- **コンテナ**: アプリと、それを動かすのに必要なファイルが、今のOSの上で動いている実体です。
- **仮想マシン**: アプリのために、別のカーネルを持つ別のOSを動かす仕組みです。
- **イメージ**: コンテナを動かすためのファイルと設定を、一つに束ねたものです。
- **カーネル**: OSの中心で、アプリとコンピュータ本体の仲立ちをする部分です。
