## この章のゴール

- [[コンテナ]]と[[仮想マシン]]の違いを、図を指しながら説明できる
- [[イメージ]]が何かを、一文で説明できる
- 失敗したコマンドの1行目から、拒否されたオプションを読み取れる

## 前提

前の章はありません。

新しい言葉は、この章で説明します。Linux の知識は要りません。

用意するものは、端末を開けるコンピュータだけです。Windows では PowerShell を開きます。Linux では Ubuntu の端末を開きます。

## 手を動かす

Linux コンテナは、自分用の別の OS を持ちません。自分が動いている Linux のカーネルを使います。Windows と Mac では、その Linux は、Docker が裏で動かす小さな Linux です。使うのは、その Linux のカーネルです。Windows 本体のカーネルや、Mac の OS（macOS）のカーネルは使いません。

仮想マシンは、OS ごと別に動かします。その OS は、自分のカーネルを持ちます。

まず、コンテナが使う Linux のカーネルを見てください。まだ Docker は動かしません。Linux では、今のパソコンの Linux のカーネルです。Windows では、WSL の中の Linux のカーネルです。WSL は、Windows の中で Linux を動かす仕組みです。Windows 本体のカーネルは見ません。

[[カーネル]]は、OSの中心で、アプリとコンピュータ本体の仲立ちをする部分です。

:::windows
実行場所は、PowerShell です。スタートメニューで「PowerShell」と検索して開きます。コマンドプロンプトではありません。

`wsl` は、Windows から Linux を呼ぶコマンドです。WSL は、Windows の中で Linux を動かす仕組みです。入れる手順は第2章です。この教科書を書いた環境は Linux で、PowerShell も WSL も実行できていません。

1. Linux カーネルの名前を表示します。

```powershell
wsl uname -s
```

何をするコマンドか。 `wsl` は、既定の Linux の中で、続くコマンドを実行します。 `uname` は、その Linux の情報を表示します。 `-s` は、カーネルの名前だけを出すオプションです。GNU coreutils 9.4 の `uname --help` では、`-s` と `--kernel-name` は同じ意味です。このオプションの意味は Linux 側で見ました。見るのは、WSL の中の Linux のカーネルです。Windows 本体のカーネルは見ません。PowerShell で実行した画面は、この環境では見ていません。

期待する出力。

未確認。この教科書を書いた環境は Linux で、PowerShell も WSL も実行できませんでした。Linux 側の `uname -s` は `Linux` でした。WSL の画面は見ていません。

出力が違うとき。 `wsl` が見つからない旨なら、WSL がまだありません。第2章で入れます。`Linux` と出れば、この手順は成功です。

2. Linux カーネルの版を表示します。

```powershell
wsl uname -r
```

何をするコマンドか。 手順1と同じ `wsl` と `uname` です。 `-r` は、カーネルのリリースを出すオプションです。`--help` では、`-r` と `--kernel-release` は同じ意味です。[公式の説明](https://docs.docker.com/desktop/features/wsl/) では、WSL 2 は完全な Linux カーネルで、複数の Linux がその一つのカーネルを使います。Docker Desktop の Windows では、この WSL 2 が標準の裏側です。このコマンドが見るのは、その Linux カーネルです。Windows 本体のカーネルではありません。WSL 2 上の Linux コンテナが使うのも、このカーネルです。

期待する出力。

未確認。この環境では PowerShell も WSL も実行できませんでした。版の数字はパソコンごとに違います。見ていない出力は、ここに書きません。

出力が違うとき。 英字や数字が1行で出ていれば、成功です。数字が Linux 側の例と違っても、失敗ではありません。コマンドが見つからない旨なら、PowerShell で、WSL を入れたあとに実行してください。
:::

:::linux
実行場所は、Ubuntu の端末です。

1. カーネルの名前を表示します。

```bash
uname -s
```

何をするコマンドか。 `uname` は、今のマシンの情報を表示します。 `-s` は、カーネルの名前だけを出すオプションです。GNU coreutils 9.4 の `uname --help` では、`-s` と `--kernel-name` は同じ意味です。オプションを二つ重ねているのではありません。

期待する出力。

```text
Linux
```


出力が違うとき。 コマンドが見つからない旨の表示が出たら、Ubuntu の端末ではありません。WSL2 の Ubuntu、または Linux の端末を開いてください。`Darwin` と出たら macOS です。この教科書の Linux 側は Ubuntu で確認しています。

2. カーネルの版を表示します。

```bash
uname -r
```

何をするコマンドか。 `uname` は、今のマシンの情報を表示します。 `-r` は、カーネルのリリースを出すオプションです。`--help` では、`-r` と `--kernel-release` は同じ意味です。

期待する出力。

```text
6.12.94+
```


出力が違うとき。 数字が違っても、失敗ではありません。カーネルの版は、パソコンごとに違います。英字や数字が1行で出ていれば、この手順は成功です。コマンドが見つからない旨の表示が出たら、手順1と同じく Ubuntu の端末で実行してください。
:::

## 何が起きたか

「手を動かす」で打ったコマンドは、2つです。1つは、カーネルの名前を出します。もう1つは、カーネルの版を出します。Docker は動かしていません。Linux では、今のパソコンの Linux で、カーネルの名前と版が出ただけです。Windows のコマンドは、WSL の中の Linux のカーネルを見るものです。Windows 本体のカーネルは見ません。この Windows のコマンドは、この環境では実行できていません。

コンテナは、自分用の別の OS を持ちません。動くのに必要なファイルを持っています。使うのは、動いている Linux のカーネルです。複数のコンテナは、同じカーネルを使います。[公式の説明](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-a-container/)。仮想マシンは、自分のカーネルを持つ OS を、別に動かします。これも、同じページに書いてあります。

コンテナが使うカーネルは、そのコンテナが動いている Linux のものです。Windows と Mac では、その Linux は、Docker が裏で動かす小さな Linux です。Mac では、Docker のプログラムとコンテナは、Docker が管理する軽い Linux の中で動きます。[Mac の公式の説明](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/)。使うのは、その Linux のカーネルです。macOS 本体のカーネルは使いません。

Windows の Docker は、標準で WSL 2 を裏側に使います。WSL 2 は、完全な Linux カーネルです。[Windows の公式の説明](https://docs.docker.com/desktop/features/wsl/)。その上の Linux は、この一つのカーネルを使います。WSL 2 上のコンテナが使うのも、この Linux カーネルです。Windows 本体のカーネルは使いません。

イメージは、コンテナを動かすためのファイルと設定を、一つに束ねたものです。まだ起動していません。起動した実体がコンテナです。イメージの中身が層になっている話は、第5章で見ます。

## 壊してみる

存在しないオプションを渡して、エラーの1行目の読み方を覚えます。失敗させてください。

:::windows
実行場所は、PowerShell です。

1. 存在しないオプションを渡します。

```powershell
wsl uname --not-a-real-option
```

何をするコマンドか。 `wsl` は、既定の Linux の中で `uname` を実行します。 `--not-a-real-option` は、わざと存在しない長いオプションです。`--help` の一覧に、この名前はありません。

期待する出力。

未確認。この環境では PowerShell も WSL も実行できませんでした。成功する出力を想像して、ここに書くことはしません。Linux 側で同じオプションを渡したときのメッセージは、Linux タブにあります。

出力が違うとき。 `Linux` とだけ出たら、オプションを付け忘れています。`wsl` が見つからない旨なら、WSL がまだありません。第2章で入れます。
:::

:::linux
実行場所は、Ubuntu の端末です。

1. 存在しないオプションを渡します。

```bash
uname --not-a-real-option
```

何をするコマンドか。 `uname` は、今のマシンの情報を表示します。 `--not-a-real-option` は、わざと存在しない長いオプションです。`--help` の一覧に、この名前はありません。

期待する出力。

```text
uname: unrecognized option '--not-a-real-option'
Try 'uname --help' for more information.
```

終了ステータスは 1 でした。成功のときのように、画面へ情報の1行だけが出るわけではありません。

出力が違うとき。 `Linux` とだけ出たら、オプションを付け忘れています。コマンドが見つからない旨なら、Ubuntu の端末ではありません。文言が少し違っても、1行目に `uname` と、入力したオプションが含まれていれば、同じ種類の失敗です。
:::

Linux で確認できたメッセージは、こう読みます。

1行目のコロンの左は、失敗したコマンドの名前です。ここでは `uname` です。右側は、理由です。`unrecognized option` は、そのオプションを知らない、という意味です。引用符の中が、今入力したものです。

2行目は、次に試すコマンドの案内です。`--help` を付けると、使えるオプションの一覧が出ます。

## 確認テスト

文章で答えてください。コマンドを実行しなくても答えられます。

:::quiz
コンテナは、仮想マシンと比べて、何を新しく作りませんか。
:::answer
アプリのために、別のOSを新しく作りません。
:::explain
仮想マシンは、OS ごと別に動かします。その OS は、自分のカーネルを持ちます。Linux コンテナは、自分用の別の OS を作りません。自分が動いている Linux のカーネルを使います。Windows と Mac では、その Linux は Docker が裏で動かす小さな Linux です。Windows 本体のカーネルや、macOS 本体のカーネルは使いません。WSL 2 上のコンテナが使うのも、WSL 2 の Linux カーネルです。
:::

:::quiz
イメージとコンテナは、どう違いますか。
:::answer
イメージは、動かすためのファイルと設定を束ねたものです。コンテナは、それを起動した実体です。
:::explain
イメージは、まだ動いていません。第4章で `docker run` を使うと、イメージからコンテナが起動します。
:::

:::quiz
`uname: unrecognized option '--not-a-real-option'` の1行目から、何が分かりますか。
:::answer
`uname` が、`--not-a-real-option` を知らないオプションとして拒否した、と分かります。
:::explain
コロンの左がコマンド名です。右側の理由に、入力したオプションが引用されています。この読み方は、Docker のエラーでも使います。
:::

## まとめ

- **コンテナ**: 自分が動いている Linux のカーネルを使って動く実体です。Windows と Mac では、その Linux は Docker が裏で動かす小さな Linux で、Windows 本体や macOS 本体のカーネルは使いません。
- **仮想マシン**: アプリのために、自分のカーネルを持つ別の OS を動かす仕組みです。
- **イメージ**: コンテナを動かすためのファイルと設定を、一つに束ねたものです。
- **カーネル**: OSの中心で、アプリとコンピュータ本体の仲立ちをする部分です。
