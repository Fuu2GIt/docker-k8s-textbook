## この章のゴール

- [[Dockerfile]] から、小さな Web アプリのイメージを作れるようになる
- そのイメージをコンテナとして起動できる
- EXPOSE が、ポートの公開そのものではないと説明できる

## 前提

第5章まで終わっていて、`docker image ls` が動きます。作業ディレクトリは `$HOME/docker-learn` です。無ければ `mkdir -p "$HOME/docker-learn"` を実行します。

実行場所は、Ubuntu の端末です。Windows では、[[WSL2]] の Ubuntu です。ファイルも、その Linux 側に作ります。

アプリは Python です。標準ライブラリだけで動きます。追加のインストールは要りません。Python を知らなくても、ファイルの全文を写せば動きます。

## 手を動かす

アプリは、ブラウザから開くと「こんにちは」と返すだけのサーバです。この章では、イメージを作って起動し、起動のログを見ます。自分のブラウザから開くのは、第7章です。

2. アプリのファイルを作ります。

```bash
cat > "$HOME/docker-learn/ch06/app.py" <<'EOF'
import os
from http.server import BaseHTTPRequestHandler, HTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        message = os.environ.get("APP_MESSAGE", "こんにちは")
        body = message.encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)


def main():
    port = int(os.environ.get("PORT", "8000"))
    server = HTTPServer(("0.0.0.0", port), Handler)
    print(f"listening on {port}", flush=True)
    server.serve_forever()


if __name__ == "__main__":
    main()
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `cat` は、入力を出力へ流します。ファイル名を付けず、`>` で行き先を `app.py` にしています。 `<<'EOF'` から次の `EOF` の直前までが、その入力です。引用符付きの `'EOF'` なので、中の文字は展開されません。このファイルと同じものを、リポジトリの `samples/ch06/app.py` に置いてあります。

`import` は、Python の標準機能を読み込みます。 `Handler` は、GET という取得の要求が来たときに呼ばれる処理です。 `os.environ.get` は、外から渡された名前付きの値を読み、無ければ2つ目の文字を使います。 `encode` は、文字を UTF-8 のバイト列にします。 `send_response(200)` は、成功の番号を返します。 `HTTPServer` は、待ち受けるサーバです。 `0.0.0.0` は、コンテナの中のすべての入口で待つ、という指定です。 `8000` は、コンテナの中のポート番号です。 `if __name__` の行は、このファイルを直接実行したときだけ `main` を呼ぶ、という Python の書き方です。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。中身はファイルに入ります。

出力が違うとき。 画面に Python のコードが出たら、`>` が抜けています。ファイルはできていません。コマンドを、`cat` から最後の `EOF` までコピーし直してください。

```python file=samples/ch06/app.py
import os
from http.server import BaseHTTPRequestHandler, HTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        message = os.environ.get("APP_MESSAGE", "こんにちは")
        body = message.encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)


def main():
    port = int(os.environ.get("PORT", "8000"))
    server = HTTPServer(("0.0.0.0", port), Handler)
    print(f"listening on {port}", flush=True)
    server.serve_forever()


if __name__ == "__main__":
    main()
```

3. Dockerfile を作ります。

```bash
cat > "$HOME/docker-learn/ch06/Dockerfile" <<'EOF'
FROM python:3.12-slim
WORKDIR /app
COPY app.py /app/app.py
EXPOSE 8000
CMD ["python", "app.py"]
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 書き方は手順2と同じです。行き先が `Dockerfile` です。この名前は、ビルドが標準で読むファイル名です。`docker build --help` には、Dockerfile の既定名が `PATH/Dockerfile` とあります。

`FROM python:3.12-slim` は、ベースイメージを決めます。ベースイメージは、自分のファイルを乗せる前の土台です。公式の [Dockerfile reference](https://docs.docker.com/reference/dockerfile/) では、Dockerfile は FROM で始まると書いてあります。 `python:3.12-slim` は、Python を動かす最小限のパッケージだけを含む公式イメージです。Docker Hub の [python 公式イメージ](https://hub.docker.com/_/python) では、slim は既定のタグに入っている一般的な Debian パッケージを含まない、と書いてあります。 `WORKDIR /app` は、以後の作業ディレクトリを `/app` にします。無ければ作ります。 `COPY app.py /app/app.py` は、ビルドの文脈にある `app.py` を、イメージの中の `/app/app.py` へコピーします。 `EXPOSE 8000` は、このイメージが 8000 番で待つ予定だ、というメモです。公式の説明では、EXPOSE はポートを公開しません。公開は第7章の `-p` です。 `CMD ["python", "app.py"]` は、コンテナ起動時に実行するコマンドです。この角括弧の形は、exec 形式です。公式の説明では、CMD は1つだけが有効です。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

出力が違うとき。 画面に `FROM` の行が出たら、`>` が抜けています。`cat` から `EOF` までをコピーし直してください。

```dockerfile file=samples/ch06/Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY app.py /app/app.py
EXPOSE 8000
CMD ["python", "app.py"]
```

## 何が起きたか

ビルドは、ベースイメージ `python:3.12-slim` の上に、作業ディレクトリ、`app.py`、EXPOSE のメモ、起動コマンドを足しました。履歴の上4行が、その足した段です。

起動したコンテナは、CMD の `python app.py` を実行し、`listening on 8000` と出しました。8000 番はコンテナの中だけで待っています。自分のパソコンのブラウザのアドレスに、まだこのアプリは出ません。

## 壊してみる

存在しないタグを FROM に書いて、ビルドのエラーを読みます。

1. 壊れた Dockerfile を作ります。

```bash
mkdir -p "$HOME/docker-learn/ch06-bad" && printf '%s\n' 'FROM python:this-tag-does-not-exist' > "$HOME/docker-learn/ch06-bad/Dockerfile"
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `mkdir -p` は、ディレクトリを作ります。 `&&` は、左が成功したときだけ右を実行するシェルの書き方です。 `printf` は、1行を出します。 `>` は、その出力を Dockerfile へ書きます。中身は、わざと存在しないタグの FROM だけです。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で、同じファイルを作ってから次のビルドを実行しました。この作成コマンドの終了ステータスは 0 です。

出力が違うとき。 `FROM` の行が画面に出たら、`>` が抜けています。コマンドをコピーし直してください。

2. 壊れた Dockerfile でビルドします。

```bash
docker build -t memo:broken "$HOME/docker-learn/ch06-bad"
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker build` は、イメージを作ります。 `-t` は、名前 `memo:broken` を付けるオプションです。最後の引数は、壊れた Dockerfile があるディレクトリです。

## 確認テスト

文章で答えてください。新しいコマンドを実行しなくても答えられます。

:::quiz

WORKDIR、COPY、EXPOSE、CMD が上にあります。PYTHON_VERSION の行は、土台の Python イメージのものです。
:::

## まとめ

- **Dockerfile**: イメージの材料と手順を書いたファイルです。ビルドは、このファイルを標準で読みます。
- **ビルド**: Dockerfile に従って、イメージを作る作業です。`docker build` がそれを行います。
- **ベースイメージ**: FROM で指定する、自分のファイルを乗せる前の土台です。

## 片付け

起動したコンテナと、壊した実験用ディレクトリを消します。イメージ `memo:ch06` と、`ch06` のソースは残します。第7章で使います。

1. アプリのコンテナを止めます。

```bash
docker stop memo-ch06
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker stop` は、動いているコンテナを止めます。引数は、コンテナ名です。オプションは付けていません。このアプリは停止の合図で自分から終わらないことがあり、約10秒待ってから止まりました。

期待する出力。

```text
memo-ch06
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

出力が違うとき。 `No such container` なら、既にありません。次へ進んでください。

2. 止めたコンテナを消します。

```bash
docker rm memo-ch06
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `docker rm` は、コンテナを消します。引数は、コンテナ名です。オプションは付けていません。イメージは消えません。

期待する出力。

```text
memo-ch06
```

この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

出力が違うとき。 動いている旨なら、手順1が終わっていません。`docker stop memo-ch06` のあと、もう一度消してください。

3. 実験用ディレクトリを消します。

```bash
rm -r "$HOME/docker-learn/ch06-bad"
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。 `rm` は、ファイルを消します。 `-r` は、ディレクトリの中も再帰的に消すオプションです。この環境の `rm --help` には、remove directories and their contents recursively とあります。消すのは、壊した実験のディレクトリだけです。`ch06` は消しません。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

出力が違うとき。 ディレクトリが無い旨なら、既に消えています。`ch06` を消してしまったときは、手順2と手順3のファイル作成からやり直してください。
