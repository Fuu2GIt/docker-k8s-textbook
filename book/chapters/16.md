## この章のゴール

- [[ConfigMap]] に書いた文字を、アプリの応答にできる
- [[Secret]] の値を、Pod の中の [[環境変数]] として読める
- [[文字列データ]] は書き込み用で、API から読み返す値ではないと説明できる

## 前提

第14章の Deployment と、第15章の Service を使います。イメージは `memo:ch13` です。アプリは、環境変数 `APP_MESSAGE` があればその文字を返し、無ければ `podから` を返します。

実行場所は、Ubuntu の端末です。Windows では、[[WSL2]] の Ubuntu です。この章のコマンドは、どちらも同じです。

3. Secret を作ります。

```bash
cat > secret.yaml <<'EOF'
apiVersion: v1
kind: Secret
metadata:
  name: memo
  namespace: memo
type: Opaque
stringData:
  APP_TOKEN: local-only
EOF
```

何をするコマンドか。 実行場所は、Ubuntu の端末です。同じファイルを `samples/ch16/secret.yaml` に置いてあります。 `kind: Secret` は、秘密の値の入れ物だと API に伝えます。 `type: Opaque` は、このファイルで指定した型です。 `stringData` は、このクラスタの explain では、バイナリではない秘密の値を文字列で渡す欄です。書き込み専用で、書いたキーと値は `data` へまとめて保存されます。API から読むとき、`stringData` は返ってきません。この値が文字列データです。 `APP_TOKEN` は `local-only` です。教科書の例なので、本番のパスワードは書かないでください。書いた値は、API では `data` に base64 で保存されます。base64 は、バイト列を決まった文字の並びへ移す方式です。暗号ではありません。公式の [Secrets の良い実践](https://kubernetes.io/docs/concepts/security/secrets-good-practices/) では、Secret の値は base64 の文字列になり、既定では暗号化されずに保存される、と書いてあります。同じページは、このファイルを共有したり、ソースの保管場所へ登録したりすると、読める人全員が秘密を見られる、とも書いています。Git は、ファイルの変更を履歴として残す仕組みです。この `secret.yaml` を Git へ上げないでください。上げた YAML は、履歴に残ります。

期待する出力。

何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。`samples/ch16/secret.yaml` とバイト単位で一致しました。

出力が違うとき。 YAML が画面に出たら、`>` が抜けています。コマンドをコピーし直してください。

```yaml file=samples/ch16/secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: memo
  namespace: memo
type: Opaque
stringData:
  APP_TOKEN: local-only
```

## 何が起きたか

ConfigMap と Secret は、Pod の外に置いた値です。Deployment の `env` が、そのキーを環境変数へコピーします。アプリのコードは `設定から` という文字を持っていません。環境変数が、初期値の `podから` を置き換えます。

この執筆環境では、Secret の API の `data.APP_TOKEN` も読みました。中身は `local-only` でした。`stringData` は、読む側の結果には入っていませんでした。手順には、その読み出しコマンドは入れていません。手順11の `printenv` が、Pod から見た値です。

`data` に入る値は base64 です。暗号ではありません。公式の [Secrets](https://kubernetes.io/docs/concepts/configuration/secret/) では、Secret は既定では、API サーバの保存先 etcd に暗号化されずに置かれる、と書いてあります。etcd は、クラスタのデータを置く保存場所です。一覧に値が出なくても、API を読める人は値を取り出せます。手順3で書いたとおり、この `secret.yaml` は Git へ上げません。

:::explain

:::

## まとめ

- **ConfigMap**: 設定の文字列を、Pod の外に置くリソースです。この章では `APP_MESSAGE` を入れました。
- **Secret**: 秘密の値を、Pod の外に置くリソースです。保存は base64 だけで、既定では暗号化されません。一覧には値そのものは出ません。
- **文字列データ**: Secret に文字列を渡すための書き込み専用の欄です。API から読むときは返ってきません。

## 片付け

ConfigMap、Secret、Deployment、Service は消しません。第17章は、別の Pod でディスクを試します。アプリの Deployment はそのまま残します。
