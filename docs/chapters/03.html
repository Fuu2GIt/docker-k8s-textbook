    第1部 準備と基礎

    第3章 コマンドラインの基礎

    目安は約35分です。

    確認したバージョン

    この章では Docker のコマンドは使いません。端末の操作だけです。

    2026-10-16 に、この環境の GNU bash 5.2.21 と GNU coreutils 9.4 で、help cd、pwd --help、mkdir --help、ls --help、cat --help、rm --help、help printf を実行して確認しました。coreutils のウェブマニュアルは、第1章と同じく、この環境から本文を読めていません。意味は、各コマンドの --help に書いてある文を使います。

    この章のゴール

    • 今いる場所を表示し、作業用のディレクトリへ移動できる
    • 短いファイルを作り、中身を表示できる
    • 失敗したコマンドの1行目から、無いファイルだと読み取れる

    前提

    第2章まで終わっていて、端末を開けます。

    Windows では、スタートメニューから Ubuntu を開きます。WSL2 の中の Ubuntu です。この章のコマンドは Linux と同じなので、タブには分けません。実行場所は、Ubuntu の端末です。この執筆環境は Ubuntu そのもので、WSL2 の窓では実行していません。

    Docker Engine は、この章では使いません。

    たとえ話

    机の上を想像してください。

    今座っている机が、カレントディレクトリです。カレントディレクトリは、端末が今いるディレクトリです。引き出しの住所が、パスです。パスは、ファイルの場所を書いた名前です。ファイルを新しく置くときは、今の机の上に置きます。

    手を動かす

    作業用のディレクトリを一つ作ります。以後の章でも、ここを使います。

    1. ホームへ移動します。
    cd "$HOME"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 cd は、カレントディレクトリを変えるシェルのコマンドです。この環境の help cd には、指定したディレクトリへ移る、と書いてあります。 "$HOME" は、自分のホームディレクトリのパスに置き換わります。引用符は、パスを1語として渡すためです。オプションは付けていません。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。終了ステータスは、コマンドが終わったときの成功と失敗の番号です。成功は 0 です。移動したかどうかは、次のコマンドで見ます。

    出力が違うとき。 ホームが無い旨なら、Ubuntu の端末ではありません。WSL2 の Ubuntu、または Linux の端末を開いてください。

    1. 今いる場所を表示します。
    pwd

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 pwd は、カレントディレクトリの名前を表示します。この環境の pwd --help には、current working directory を表示する、と書いてあります。オプションは付けていません。

    期待する出力。

    /home/ubuntu

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。/home/ の後ろは利用者名です。自分のパソコンでは、ubuntu の部分が自分の名前になります。

    出力が違うとき。 /mnt/c で始まるときは、Windows 側のフォルダにいます。手順1をもう一度実行してください。1行のパスが出ていれば、名前が違っても成功です。

    1. 作業用ディレクトリを作ります。
    mkdir -p "$HOME/docker-learn"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 mkdir は、ディレクトリを作ります。 -p は、既にあってもエラーにせず、途中のディレクトリも必要なら作るオプションです。この環境の mkdir --help には、--parents と同じ、と書いてあります。 "$HOME/docker-learn" は、ホームの中の docker-learn です。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。2回目も何も出ません。-p があるためです。

    出力が違うとき。 File exists と出たら、-p が抜けています。コマンドをコピーし直してください。Permission denied なら、ホーム以外の場所へ作ろうとしています。"$HOME/docker-learn" をそのまま使ってください。

    1. 作業用ディレクトリへ移動します。
    cd "$HOME/docker-learn"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 cd は、カレントディレクトリを変えます。引数は、手順3で作ったディレクトリです。オプションは付けていません。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

    出力が違うとき。 ディレクトリが無い旨なら、手順3が終わっていません。手順3からやり直してください。

    1. 移動できたかを表示します。
    pwd

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 コマンド自体は手順2と同じ pwd です。オプションは付けていません。今のカレントディレクトリを表示します。

    期待する出力。

    /home/ubuntu/docker-learn

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。利用者名の部分は、自分の名前に変わります。最後が docker-learn なら成功です。

    出力が違うとき。 最後が docker-learn でないときは、手順4が別の場所で終わっています。手順4をもう一度実行してください。

    1. 中身を、詳しい形で表示します。
    ls -la

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 ls は、ファイルの情報を表示します。引数を省略すると、カレントディレクトリを見ます。この環境の ls --help に、そう書いてあります。 -l は、長い形式で出すオプションです。 -a は、. で始まる名前も隠さないオプションです。

    期待する出力。

    total 8
drwxr-xr-x   2 ubuntu ubuntu 4096 Oct 16 17:40 .
drwxr-x---. 13 ubuntu ubuntu 4096 Oct 16 17:40 ..

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。日時と利用者名は、パソコンごとに違います。. は今のディレクトリです。.. は一つ上のディレクトリです。権限の末尾に . のような記号が付くことがあります。この環境では、上のディレクトリの行に付いていました。無くても成功です。

    出力が違うとき。 note.txt が既に見えても、前に作ったファイルが残っているだけです。この章の片付けを実行してから、手順7へ進んでください。コマンドが見つからない旨なら、Ubuntu の端末ではありません。

    1. 1行のファイルを作ります。
    printf '%s\n' 'こんにちは' > note.txt

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 printf は、書式に従って文字を出します。この環境の help printf には、書式の下で引数を表示する、と書いてあります。 '%s\n' は書式です。 %s は、次の引数をそのまま出す指定です。 \n は、改行です。 'こんにちは' は、出す文字です。 > はコマンドのオプションではありません。標準出力は、コマンドが結果を流す通り道です。 > は、その行き先を右のファイルへ変えます。この書き方をリダイレクトと呼びます。ファイルが無ければ作り、あれば中身を置き換えます。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。文字は画面ではなく note.txt に入っています。

    出力が違うとき。 画面に こんにちは と出たら、> 以降が抜けています。ファイルはできていません。コマンドをコピーし直してください。

    1. ファイルの中身を表示します。
    cat note.txt

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 cat は、ファイルの中身を標準出力へ出します。この環境の cat --help には、concatenate FILE(s) to standard output と書いてあります。引数の note.txt は、手順7で作ったファイルです。これは相対パスです。カレントディレクトリの中を探します。オプションは付けていません。

    期待する出力。

    こんにちは

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 ファイルが無い旨なら、カレントディレクトリが手順5と違います。pwd の最後が docker-learn であることを確認し、手順7からやり直してください。

    1. 相対パスで、ファイルがあることを見ます。
    ls note.txt

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 ls は、ファイルの情報を表示します。引数の note.txt は相対パスです。-l も -a も付けていません。名前だけを見ます。

    期待する出力。

    note.txt

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 ファイルが無い旨なら、手順7が終わっていません。手順5の場所に戻してから、手順7を実行してください。

    1. 絶対パスで、同じファイルを見ます。
    ls "$HOME/docker-learn/note.txt"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 ls は、ファイルの情報を表示します。 "$HOME/docker-learn/note.txt" は絶対パスです。/ から始まるので、今いる場所に関係なく同じファイルを指します。オプションは付けていません。

    期待する出力。

    /home/ubuntu/docker-learn/note.txt

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。利用者名の部分は、自分の名前に変わります。

    出力が違うとき。 ファイルが無い旨なら、パスの綴りが違います。コマンドをコピーし直してください。表示されたパスの最後が note.txt なら、途中の名前が違っても成功です。

    何が起きたか

    手順1から5で、カレントディレクトリをホームから docker-learn へ移しました。手順7の > は、printf の標準出力を画面からファイルへ差し向けました。手順9の note.txt は相対パスです。手順10の $HOME から始まる指定は絶対パスです。どちらも同じファイルです。

    左は、今いる場所からの名前です。右は、先頭の / から辿る名前です。カレントディレクトリがどこでも、右は同じファイルを指します。

    壊してみる

    無いファイルを表示して、エラーの1行目を読みます。

    1. 存在しないファイルを指定します。
    ls missing.txt

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 ls は、ファイルの情報を表示します。 missing.txt は、わざと作っていない相対パスです。オプションは付けていません。

    期待する出力。

    ls: cannot access 'missing.txt': No such file or directory

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 2 でした。成功のときは 0 です。

    出力が違うとき。 missing.txt とだけ出たら、同じ名前のファイルが本当にあります。rm missing.txt で消してから、もう一度実行してください。この削除コマンドは、そのファイルが自分で作ったものであることを確認してから実行します。

    1行目は、コロンで区切ります。左の ls が、失敗したコマンドです。cannot access は、その名前を開けなかった、という意味です。引用符の中が、指定したパスです。No such file or directory は、そのファイルもディレクトリも無い、という意味です。

    確認テスト

    文章で答えてください。新しいコマンドを実行しなくても答えられます。

    問題1

    pwd は、何を表示しますか。

    解答と解説

    カレントディレクトリのパスを表示します。

    今いる場所です。この章では、ホームと、その中の docker-learn を表示しました。

    問題2

    note.txt と $HOME/docker-learn/note.txt は、何が違いますか。

    解答と解説

    前者が相対パスで、後者が絶対パスです。この章の手順では、同じファイルを指します。

    相対パスは、カレントディレクトリから探します。絶対パスは、先頭の / から辿るので、今いる場所が違っても同じファイルです。

    問題3

    printf の結果が画面に出ず、ファイルに入った理由は何ですか。

    解答と解説

    > が、標準出力の行き先を note.txt に変えたからです。

    > は printf のオプションではありません。シェルが、画面へ出るはずの出力をファイルへ書きます。

    まとめ

    • カレントディレクトリ: 端末が今いるディレクトリです。相対パスは、ここから探します。
    • パス: ファイルやディレクトリの場所を書いた名前です。先頭が / なら絶対パス、そうでなければ相対パスです。
    • 標準出力: コマンドが結果を流す、画面へ向かう出力の通り道です。
    • リダイレクト: > で、標準出力の行き先をファイルへ変える書き方です。
    • 終了ステータス: コマンドが終わったときの成功と失敗の番号です。成功は 0 で、失敗は 0 以外です。

    片付け

    手順7で作ったファイルを消します。ディレクトリは、次の章でも使うので残します。

    1. 練習ファイルを消します。
    rm note.txt

    何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは $HOME/docker-learn のままにします。 rm は、ファイルを消します。引数の note.txt は、消す相対パスです。オプションは付けていません。ディレクトリは消しません。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。消えたあとの ls -la は、. と .. だけの表示に戻りました。

    出力が違うとき。 ファイルが無い旨なら、既に消えています。そのままで次の章へ進んでよいです。カレントディレクトリが違う旨なら、cd "$HOME/docker-learn" を実行してから、もう一度消してください。
