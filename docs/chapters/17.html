    第17章 永続ボリューム

    目安は約40分です。

    確認したバージョン

    2026-10-16 に、次を確認しました。

    • Persistent Volumes
    • Storage Classes
    • このクラスタの kubectl explain persistentvolumeclaim.spec.accessModes
    • このクラスタの kubectl explain persistentvolumeclaim.spec.storageClassName
    • このクラスタの kubectl explain pod.spec.restartPolicy
    • このクラスタの kubectl explain pod.spec.containers.command
    • kubectl wait --help

    クラスタは Kubernetes v1.37.0 です。クライアントは kubectl v1.37.1 です。公式の Persistent Volume の説明では、ReadWriteOnce は、ボリュームを1つのノードから読み書きでマウントできる、と書かれています。同じノード上の複数の Pod が、そのボリュームへアクセスできる場合もあります。

    この章のゴール

    • 永続ボリューム要求 を作り、Pod が使うまで Pending だと確認できる
    • 書き込んだ文字を、その Pod を消したあとに別の Pod から読める
    • アクセスモード の値が不正だと、作成が拒否されると確認できる

    前提

    第13章のイメージ memo:ch13 が、kind のノードに載っています。名前空間 memo と、第16章の Deployment は残します。この章で作るのは、書き込み用と読み取り用の Pod と、ディスクの要求だけです。

    第8章の ボリューム は、Docker がコンテナのために持つ保存場所です。この章の永続ボリューム要求は、Kubernetes の Pod がディスクを求める宣言です。同じ言葉でも、指すものは違います。

    ストレージクラス は、ディスクの用意の仕方に付けた名前です。再起動ポリシー は、Pod の中のコンテナが終わったあと、もう一度起動するかの指定です。このクラスタの explain では、Always、OnFailure、Never のいずれかで、既定は Always です。

    実行場所は、Ubuntu の端末です。Windows では、WSL2 の Ubuntu です。この章のコマンドは、どちらも同じです。

    たとえ話

    貸ロッカーを想像してください。

    確認テスト

    文章で答えてください。新しいコマンドを実行しなくても答えられます。

    問題1

    要求を作った直後の STATUS が Pending だったのは、なぜですか。

    解答と解説

    ストレージクラスの結合モードが WaitForFirstConsumer で、使う Pod がまだ無かったからです。

    公式の説明では、このモードは、要求を使う Pod ができるまで、ボリュームの結合と用意を遅らせます。Pod のあと、STATUS は Bound になりました。

    問題2

    書き込み用の Pod を消したあとに、文字が残っていたことを、どの出力で確認しましたか。

    解答と解説

    読み取り用の Pod のログが 残るメモ だったことです。

    2つの Pod は別の名前です。同じ要求 memo-data を、/data に見せました。

    問題3

    restartPolicy: Never を書いたのは、なぜですか。

    解答と解説

    終わったコマンドを、既定の Always で繰り返さないためです。

    explain では、再起動ポリシーの既定は Always です。Never にすると、正常に終わった Pod の phase は Succeeded で止まれます。

    まとめ

    • 永続ボリューム要求: Pod が欲しい容量とアクセスの仕方を書いたリソースです。Pod を消しても、要求は残ります。
    • ストレージクラス: ディスクの用意の仕方に付けた名前です。このクラスタの standard は、最初の Pod まで結合を待ちます。
    • アクセスモード: ボリュームをどうマウントするかの指定です。ReadWriteOnce は、1つのノードから読み書きできるモードです。
    • 再起動ポリシー: コンテナが終わったあと、もう一度起動するかの指定です。既定は Always で、この章の2つの Pod は Never です。
