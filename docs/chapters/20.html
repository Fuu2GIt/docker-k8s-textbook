    第20章 AWSへのつながり

    目安は約25分です。

    確認したバージョン

    2026-10-16 に、次の公式ページを開きました。

    • What is Amazon Elastic Container Registry?
    • What is Amazon Elastic Container Service?
    • What is Amazon EKS?

    同じ日に、手元の docker image ls memo:ch13 と kubectl get deployment を実行しました。Docker Engine は 29.9.1、kubectl は v1.37.1、クラスタは Kubernetes v1.37.0 です。

    AWS へのログインと、AWS のコマンドは、この章では実行していません。画面の操作手順も書きません。

    この章のゴール

    • 手元のイメージが、AWS では ECR に置くものだと説明できる
    • 手元でコンテナを動かす役割が、ECS に対応すると説明できる
    • この kind のクラスタが、EKS ではコントロールプレーンを AWS が持つ Kubernetes だと説明できる

    前提

    第10章までのイメージと、第12章から第19章までの kind のクラスタを使います。レジストリ は、イメージを置いて配る場所です。手元では Docker Hub の docker.io を使ってきました。

    実行場所は、Ubuntu の端末です。Windows では、WSL2 の Ubuntu です。この章の2つの確認コマンドは、どちらも同じです。

    たとえ話

    引越しを想像してください。

    段ボールを預ける倉庫が ECR です。配達の手配が ECS です。倉庫の管理室を自分で持たず、業者に任せるのが EKS です。

    手を動かす

    1. 手元のイメージを見ます。
    docker image ls memo:ch13

    何をするコマンドか。 実行場所は、Ubuntu の端末です。Windows では、WSL2 の Ubuntu です。 docker image ls は、手元のイメージを表示します。引数 memo:ch13 は、第13章で付けた名前です。

    期待する出力。

    IMAGE       ID             DISK USAGE   CONTENT SIZE   EXTRA
memo:ch13   a5ab2fd5a7e1        177MB         43.3MB

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。ID と容量の数字は違ってよいです。 memo:ch13 が1行で出ることを確認してください。このイメージは、自分のパソコンの Docker にあります。AWS のアカウントには、まだ送っていません。

    出力が違うとき。 行が無いなら、第13章のビルドが終わっていません。docker image ls で名前を探してください。

    1. クラスタの Deployment を見ます。
    kubectl get deployment memo -n memo --context kind-memo

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 kubectl get deployment は、Deployment を表示します。 -n memo は、名前空間です。 --context kind-memo は、第12章で作った接続先です。

    期待する出力。

    NAME   READY   UP-TO-DATE   AVAILABLE   AGE
memo   2/2     2            2           30m

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。AGE は違ってよいです。この実行では READY が 2/2 でした。Pod を2つ保つ定義が、手元の Kubernetes で動いています。

    出力が違うとき。 connection refused なら、クラスタが止まっています。第12章の kind get clusters を見てください。

    何が起きたか

    手元の作業と、AWS のサービスの対応は、次のとおりです。

    ECR は、公式の説明では、AWS が管理するコンテナイメージのレジストリです。プライベートな置き場を IAM で制限し、Docker イメージと OCI イメージを push と pull できます。第5章で外から取得したイメージと、第6章以降で自分で作った memo:ch13 は、AWS ではこの置き場に送る候補です。この章では送っていません。

    ECS は、公式の説明では、コンテナの実行をまとめて任せる、フルマネージドのサービスです。コントロールプレーンを自分で運用しない、と書かれています。用語では、タスク定義がアプリの設計図、クラスタが実行する場所、タスクが動いて終わる処理、サービスが長く動かす処理です。Kubernetes の Deployment そのものではありません。ECS は Kubernetes ではない、と切り分けて覚えてください。

    EKS は、公式の説明では、フルマネージドの Kubernetes です。標準の EKS では、クラスタを作ると AWS が Kubernetes のコントロールプレーンを管理します。kind では、コントロールプレーンもワーカーも、自分のパソコンの Docker コンテナです。EKS に移すと、コントロールプレーンの運用は AWS 側になります。ワーカーの計算資源は、別の料金です。この章では、クラスタは作っていません。

    左が、この教科書で自分のパソコンに作ったものです。右が、就職活動で名前を見る AWS のサービスです。矢印は、役割の対応です。この章では、データを送っていません。

    壊してみる

    無い名前の Deployment を見ます。

    1. 存在しない名前を指定します。
    kubectl get deployment missing-name -n memo --context kind-memo

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 missing-name は、クラスタに作っていない名前です。接続先と名前空間は、手順2と同じです。

    期待する出力。

    Error from server (NotFound): deployments.apps "missing-name" not found

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 1 でした。 NotFound は、その名前が名前空間 memo に無い、という意味です。クラスタ自体は動いています。

    出力が違うとき。 connection refused なら、クラスタに届いていません。名前のエラーとは別です。

    AWS のサービス名も、同じです。名前が似ていても、ECR と ECS と EKS は別のサービスです。無い名前を指定すると、Kubernetes は NotFound で拒否します。

    確認テスト

    文章で答えてください。新しいコマンドを実行しなくても答えられます。

    問題1

    memo:ch13 を AWS の置き場へ送るとき、まず対応するのはどのサービスですか。

    解答と解説

    ECR です。

    公式の説明では、ECR は AWS が管理するコンテナイメージのレジストリです。この章では、まだ送っていません。

    問題2

    ECS は、Kubernetes ですか。

    解答と解説

    いいえ。ECS は、Kubernetes とは別の、コンテナの実行を任せるサービスです。

    公式の ECS の説明は、コントロールプレーンを自分で運用しないコンテナのサービスです。Kubernetes として使うサービスは EKS です。

    問題3

    標準の EKS で、AWS が管理すると書かれているのは、クラスタのどの部分ですか。

    解答と解説

    Kubernetes のコントロールプレーンです。

    公式の説明では、標準の EKS はクラスタを作ると AWS がコントロールプレーンを管理します。kind では、その部分も自分のパソコンのコンテナです。

    まとめ

    • ECR: AWS が管理する、コンテナイメージのレジストリです。Docker イメージを置いて配る場所です。
    • ECS: コンテナの実行をまとめて任せる AWS のサービスです。Kubernetes そのものではありません。
    • EKS: AWS がコントロールプレーンを管理する Kubernetes です。kind で書いたマニフェストの考え方を、そのまま持ち込めます。

    片付け

    この章では、新しいコンテナもクラスタも作っていません。イメージ memo:ch13 と、クラスタ memo は残します。第21章で、最後の演習をしたあと、クラスタを消します。
