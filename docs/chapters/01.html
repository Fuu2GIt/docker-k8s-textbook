    第1部 準備と基礎

    第1章 コンテナとは何か

    目安は約25分です。

    この章のゴール

    • コンテナと仮想マシンの違いを、図を指しながら説明できる
    • イメージが何かを、一文で説明できる
    • 失敗したコマンドの1行目から、拒否されたオプションを読み取れる

    前提

    前の章はありません。

    新しい言葉は、この章で説明します。Linux の知識は要りません。

    用意するものは、端末を開けるコンピュータだけです。Windows では PowerShell を開きます。Linux では Ubuntu の端末を開きます。

    手を動かす

    Linux コンテナは、Linux カーネルを共有します。Windows と Mac では、Docker が裏で小さな Linux を動かします。仮想マシンは、別のカーネルを持つ別の OS を動かします。まず、コンテナが共有する Linux カーネルを見てください。

    カーネルは、OSの中心で、アプリとコンピュータ本体の仲立ちをする部分です。

    実行場所は、PowerShell です。スタートメニューで「PowerShell」と検索して開きます。コマンドプロンプトではありません。

    wsl は、Windows から Linux を呼ぶコマンドです。WSL は、Windows の中で Linux を動かす仕組みです。入れる手順は第2章です。この教科書を書いた環境は Linux で、PowerShell も WSL も実行できていません。

    1. Linux カーネルの名前を表示します。
    wsl uname -s

    何をするコマンドか。 wsl は、既定の Linux の中で、続くコマンドを実行します。 uname は、その Linux の情報を表示します。 -s は、カーネルの名前だけを出すオプションです。GNU coreutils 9.4 の uname --help では、-s と --kernel-name は同じ意味です。このオプションの意味は Linux 側で見ました。PowerShell で実行した画面は、この環境では見ていません。

    期待する出力。

    未確認。この教科書を書いた環境は Linux で、PowerShell も WSL も実行できませんでした。Linux 側の uname -s は Linux でした。WSL の画面は見ていません。

    出力が違うとき。 wsl が見つからない旨なら、WSL がまだありません。第2章で入れます。Linux と出れば、この手順は成功です。

    1. Linux カーネルの版を表示します。
    wsl uname -r

    何をするコマンドか。 手順1と同じ wsl と uname です。 -r は、カーネルのリリースを出すオプションです。--help では、-r と --kernel-release は同じ意味です。公式の Docker Desktop WSL 2 backend では、WSL 2 は完全な Linux カーネルで、複数の Linux がその一つのカーネルを共有します。Docker Desktop の Windows では、この WSL 2 が標準の裏側です。

    期待する出力。

    未確認。この環境では PowerShell も WSL も実行できませんでした。版の数字はパソコンごとに違います。見ていない出力は、ここに書きません。

    出力が違うとき。 英字や数字が1行で出ていれば、成功です。数字が Linux 側の例と違っても、失敗ではありません。コマンドが見つからない旨なら、PowerShell で、WSL を入れたあとに実行してください。

    実行場所は、Ubuntu の端末です。

    1. カーネルの名前を表示します。
    uname -s

    何をするコマンドか。 uname は、今のマシンの情報を表示します。 -s は、カーネルの名前だけを出すオプションです。GNU coreutils 9.4 の uname --help では、-s と --kernel-name は同じ意味です。オプションを二つ重ねているのではありません。

    期待する出力。

    Linux

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。

    出力が違うとき。 コマンドが見つからない旨の表示が出たら、Ubuntu の端末ではありません。WSL2 の Ubuntu、または Linux の端末を開いてください。Darwin と出たら macOS です。この教科書の Linux 側は Ubuntu で確認しています。

    1. カーネルの版を表示します。
    uname -r

    何をするコマンドか。 uname は、今のマシンの情報を表示します。 -r は、カーネルのリリースを出すオプションです。--help では、-r と --kernel-release は同じ意味です。

    期待する出力。

    6.12.94+

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。

    出力が違うとき。 数字が違っても、失敗ではありません。カーネルの版は、パソコンごとに違います。英字や数字が1行で出ていれば、この手順は成功です。コマンドが見つからない旨の表示が出たら、手順1と同じく Ubuntu の端末で実行してください。

    何が起きたか

    「手を動かす」で打った2つのコマンド（カーネルの名前を出すものと、版を出すもの）は、Docker を動かしていません。Linux では、今のカーネルの名前と版を画面に出しただけです。Windows のコマンドは、WSL の中の Linux カーネルを見るものです。この Windows のコマンドは、この環境では実行できていません。

    Linux コンテナは、Linux カーネルを共有します。仮想マシンは、別のカーネルを持つ別の OS を動かします。Windows と Mac では、Docker が裏で小さな Linux を動かします。コンテナは、その Linux のカーネルを共有します。Docker Docs の What is a container? では、複数のコンテナは同じカーネルを共有し、仮想マシンは自分のカーネルを持つ、と説明されています。Mac では、Docker Desktop の権限の説明 に、Docker のプログラムとコンテナは、Docker が管理する軽い Linux の仮想マシンの中で動く、と書いてあります。Windows では、WSL 2 backend に、WSL 2 は完全な Linux カーネルだと書いてあります。

    イメージは、コンテナを動かすためのファイルと設定を、一つに束ねたものです。まだ起動していません。起動した実体がコンテナです。イメージの中身が層になっている話は、第5章で見ます。

    左は仮想マシンです。アプリの下に、別の OS がいます。右はコンテナです。アプリと必要なファイルは、Linux カーネルのすぐ上で動きます。Windows と Mac では、そのカーネルは Docker が裏で動かす小さな Linux のものです。

    壊してみる

    存在しないオプションを渡して、エラーの1行目の読み方を覚えます。失敗させてください。

    実行場所は、PowerShell です。

    1. 存在しないオプションを渡します。
    wsl uname --not-a-real-option

    何をするコマンドか。 wsl は、既定の Linux の中で uname を実行します。 --not-a-real-option は、わざと存在しない長いオプションです。--help の一覧に、この名前はありません。

    期待する出力。

    未確認。この環境では PowerShell も WSL も実行できませんでした。成功する出力を想像して、ここに書くことはしません。Linux 側で同じオプションを渡したときのメッセージは、Linux タブにあります。

    出力が違うとき。 Linux とだけ出たら、オプションを付け忘れています。wsl が見つからない旨なら、WSL がまだありません。第2章で入れます。

    実行場所は、Ubuntu の端末です。

    1. 存在しないオプションを渡します。
    uname --not-a-real-option

    何をするコマンドか。 uname は、今のマシンの情報を表示します。 --not-a-real-option は、わざと存在しない長いオプションです。--help の一覧に、この名前はありません。

    期待する出力。

    uname: unrecognized option '--not-a-real-option'
Try 'uname --help' for more information.

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 1 でした。成功のときのように、画面へ情報の1行だけが出るわけではありません。

    出力が違うとき。 Linux とだけ出たら、オプションを付け忘れています。コマンドが見つからない旨なら、Ubuntu の端末ではありません。文言が少し違っても、1行目に uname と、入力したオプションが含まれていれば、同じ種類の失敗です。

    Linux で確認できたメッセージは、こう読みます。

    1行目のコロンの左は、失敗したコマンドの名前です。ここでは uname です。右側は、理由です。unrecognized option は、そのオプションを知らない、という意味です。引用符の中が、今入力したものです。

    2行目は、次に試すコマンドの案内です。--help を付けると、使えるオプションの一覧が出ます。

    確認テスト

    文章で答えてください。コマンドを実行しなくても答えられます。

    問題1

    コンテナは、仮想マシンと比べて、何を新しく作りませんか。

    解答と解説

    アプリのために、別のOSを新しく作りません。

    仮想マシンは、別のカーネルを持つ別の OS を動かします。Linux コンテナは、Linux カーネルを共有して、必要なファイルと一緒にアプリを動かします。Windows と Mac では、その Linux を Docker が裏で動かします。

    問題2

    イメージとコンテナは、どう違いますか。

    解答と解説

    イメージは、動かすためのファイルと設定を束ねたものです。コンテナは、それを起動した実体です。

    イメージは、まだ動いていません。第4章で docker run を使うと、イメージからコンテナが起動します。

    問題3

    uname: unrecognized option '--not-a-real-option' の1行目から、何が分かりますか。

    解答と解説

    uname が、--not-a-real-option を知らないオプションとして拒否した、と分かります。

    コロンの左がコマンド名です。右側の理由に、入力したオプションが引用されています。この読み方は、Docker のエラーでも使います。

    まとめ

    • コンテナ: アプリと必要なファイルが、Linux カーネルを共有して動いている実体です。
    • 仮想マシン: アプリのために、別のカーネルを持つ別のOSを動かす仕組みです。
    • イメージ: コンテナを動かすためのファイルと設定を、一つに束ねたものです。
    • カーネル: OSの中心で、アプリとコンピュータ本体の仲立ちをする部分です。

    片付け
