    第2部 Docker

    第7章 ポートとネットワーク

    目安は約40分です。

    確認したバージョン

    2026-10-16 に、次を確認しました。

    • Networking overview
    • Invoke-WebRequest
    • Docker Engine 29.9.1 の docker run --help と docker network create --help
    • curl 8.5.0 の --help all

    この章のイメージは、第6章の memo:ch06 です。

    この章のゴール

    • コンテナの 8000 番を、自分のパソコンから開ける
    • ユーザー定義ネットワーク の中で、コンテナ名を宛先にして通信できる
    • 開いていないポートへの失敗を、エラーの1行から読める

    前提

    第6章のイメージ memo:ch06 が手元にあります。コンテナ memo-ch06 は消してあります。

    実行場所は、Ubuntu の端末です。Windows では、コンテナの操作は WSL2 の Ubuntu で行います。自分のパソコンのブラウザから開く確認だけ、OSで違います。

    ポート公開 は、コンテナのポートを、自分のパソコンのポートへつなぐことです。第6章の EXPOSE は、そのメモだけで、公開ではありません。

    たとえ話

    集合住宅を想像してください。

    建物の住所が、自分のパソコンです。部屋番号が、ポートです。部屋番号を玄関の掲示板に出すのが、ポート公開です。建物の中の廊下で、部屋の名前を呼び合うのが、ユーザー定義ネットワークです。

    手を動かす

    1. 8000 番を、自分のパソコンへ公開して起動します。
    docker run --name memo-ch07 --detach --publish 8000:8000 memo:ch06

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker run は、イメージからコンテナを起動します。 --name は、コンテナ名 memo-ch07 を付けます。 --detach は、デタッチです。 --publish は、ポートを自分のパソコンから届くようにするオプションです。この環境の docker run --help には、Publish a container's port(s) to the host と書いてあります。 8000:8000 は、この実行では両方の 8000 番をつなぎました。左側が自分のパソコン、右側がコンテナです。根拠は、次の一覧と、そのポートへの取得が成功したことです。 memo:ch06 は、第6章のイメージです。

    期待する出力。

    65d5ef593fbfeb582c4c9c793f97a1cec4bee47e7e7fbc7b520468151b9a6d1d

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。64文字のコンテナIDは、実行のたびに変わります。

    出力が違うとき。 ポートが使用中という旨なら、8000 番を別のプログラムが使っています。そのプログラムを止めるか、左側の番号だけを 8001:8000 に変えてください。変えた場合は、このあとの URL のポートも 8001 にします。名前が使用中なら、docker rm -f memo-ch07 を実行してから、もう一度起動してください。

    1. 公開されたポートを一覧で見ます。
    docker ps

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker ps は、動いているコンテナを表示します。オプションは付けていません。

    期待する出力。

    CONTAINER ID   IMAGE       COMMAND           CREATED        STATUS        PORTS                                         NAMES
65d5ef593fbf   memo:ch06   "python app.py"   1 second ago   Up 1 second   0.0.0.0:8000->8000/tcp, [::]:8000->8000/tcp   memo-ch07

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。ID と時刻は変わってよいです。0.0.0.0:8000->8000/tcp の矢印の左が、自分のパソコンのすべての IPv4 入口とポートです。右が、コンテナの 8000 番です。[::] は、IPv6 のすべての入口です。第6章の 8000/tcp だけ、とは違います。

    出力が違うとき。 矢印が無いときは、--publish が付いていません。docker rm -f memo-ch07 のあと、手順1をコピーし直してください。

    次に、自分のパソコンから中身を取得します。

    1. PowerShell から、localhost を開きます。
    Invoke-WebRequest -Uri http://localhost:8000/ -UseBasicParsing

    何をするコマンドか。 実行場所は、PowerShell です。コンテナの起動は、WSL2 の Ubuntu で済ませておきます。 Invoke-WebRequest は、URL へ HTTP の要求を送ります。 -Uri は、その URL です。Microsoft Learn には、HTTP か HTTPS の URI を指定する、と書いてあります。 http://localhost:8000/ の localhost は、自分のパソコン自身を指す名前です。 -UseBasicParsing は、PowerShell 7 の説明では後方互換のためだけに残り、効果はない、と書いてあります。Windows PowerShell 5.1 でも同じコマンドを使えるように、付けています。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。Linux で http://127.0.0.1:8000/ を取得したときは、本文が こんにちは でした。ブラウザで http://localhost:8000/ を開いても、同じ文字が見えれば成功です。

    出力が違うとき。 接続を拒否された旨なら、Docker Desktop が止まっているか、手順1の公開が終わっていません。Ubuntu 側で docker ps を見て、矢印の行があることを確認してください。

    1. 自分のパソコンの 8000 番から取得します。
    curl -sS -D - http://127.0.0.1:8000/

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 curl は、URL の中身を取得します。 -s は、進捗を出さないオプションです。 -S は、-s のときでもエラーは表示するオプションです。 -D は、受け取ったヘッダの書き先を指定するオプションです。この環境のヘルプには、Write the received headers to filename とあります。 - を渡したこの実行では、ヘッダが本文の前に画面へ出ました。 http://127.0.0.1:8000/ の 127.0.0.1 は、自分のパソコン自身を指すアドレスです。最後の 8000 が、手順1で公開したポートです。

    期待する出力。

    HTTP/1.0 200 OK
Server: BaseHTTP/0.6 Python/3.12.15
Date: Fri, 16 Oct 2026 17:49:27 GMT
Content-Type: text/plain; charset=utf-8
Content-Length: 15

こんにちは

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。Date の時刻は、実行した時刻です。200 は成功です。最後の行が、アプリの返す文字です。Content-Length: 15 は、その文字を UTF-8 にしたバイト数です。

    出力が違うとき。 接続できない旨なら、手順2の矢印がありません。こんにちは 以外の文字なら、アプリの APP_MESSAGE を変えています。この章では変えていません。

    1. コンテナ同士が名前で話せるネットワークを作ります。
    docker network create memo-net

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker network create は、ネットワークを作ります。引数の memo-net は、その名前です。オプションは付けていません。標準のドライバは bridge です。この環境のヘルプには、default "bridge" とあります。公式の説明では、ユーザー定義ネットワークに繋がったコンテナは、コンテナ名で通信できます。オプション無しの既定の bridge では、名前では呼べません。

    期待する出力。

    aed284b04892beab57a22bdddb471d41b37b062386451d362f27d0e562d69b53

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。この64文字はネットワークの ID で、実行のたびに変わります。

    出力が違うとき。 既に存在する旨なら、前の実験が残っています。片付けの docker network rm memo-net を実行してから、もう一度作ってください。コンテナが残っていて消せないときは、先にそのコンテナを docker rm -f で消します。

    1. ネットワークの中で、アプリを起動します。
    docker run --name memo-net-a --detach --network memo-net memo:ch06

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker run は、コンテナを起動します。 --name は、名前 memo-net-a です。この名前を、あとで宛先に使います。 --detach は、裏で動かします。 --network は、接続するネットワークです。この環境の docker run --help には、Connect a container to a network とあります。 memo-net は、手順3のネットワークです。 --publish は付けていません。このコンテナは、同じネットワークの中からだけ開けば足ります。

    期待する出力。

    1c8c1d482bcb66df1a75917018a75b1a7be4bec08be823e86059aae829168757

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。ID は変わってよいです。

    出力が違うとき。 ネットワークが無い旨なら、手順3が終わっていません。名前が使用中なら、docker rm -f memo-net-a のあと、もう一度実行してください。

    1. 別のコンテナから、名前で取得します。
    docker run --rm --network memo-net memo:ch06 python -c 'import urllib.request; print(urllib.request.urlopen("http://memo-net-a:8000/", timeout=5).read().decode())'

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker run は、コンテナを起動します。 --rm は、終了したらコンテナを消します。 --network は、memo-net へ接続します。 memo:ch06 はイメージです。その後ろの python と -c 以降は、イメージの CMD の代わりに実行するコマンドです。docker run の形は、IMAGE [COMMAND] [ARG...] です。 -c は、Python に1行のプログラムを渡すオプションです。プログラムは、http://memo-net-a:8000/ を開き、受け取ったバイト列を文字にして表示します。 timeout=5 は、5秒で打ち切る指定です。 memo-net-a は、手順4のコンテナ名です。

    期待する出力。

    こんにちは

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。同じネットワークにいるコンテナは、相手のコンテナ名を宛先にできます。

    出力が違うとき。 Temporary failure in name resolution のように名前を引けない旨なら、--network memo-net が片方から抜けています。Connection timed out や Errno 110 のときは、名前は引けていてもパケットが落ちています。この執筆環境では、最初の実行がそこで失敗しました。iptables-legacy の FORWARD が DROP だったためです。確認のためにそのポリシーを ACCEPT へ変えてから、同じコマンドを再実行し、こんにちは を得ました。systemd で入れた通常の Ubuntu では、この変更は要りません。タイムアウトが続くときは、第2章の Docker の導入から見直してください。

    何が起きたか

    --publish 8000:8000 は、自分のパソコンの 8000 番への到着を、コンテナの 8000 番へ渡しました。curl は 127.0.0.1 に対して送り、アプリの文字が返ってきました。

    memo-net は、ユーザー定義の bridge ネットワークです。memo-net-a と、取得側の短いコンテナは、同じネットワークに入りました。取得側は、IP アドレスを書かずに memo-net-a という名前で 8000 番を開きました。公式の説明どおり、既定の bridge ではなく、自分で作ったネットワークだから名前が使えます。

    左は、自分のパソコンの入口からコンテナへ入ります。右は、ネットワークの中だけで名前が通ります。右のアプリは、パソコンの 8000 番には出していません。

    壊してみる

    開いていないポートへ接続し、拒否の文を読みます。

    1. 開いていないポートへ要求します。
    Invoke-WebRequest -Uri http://localhost:59999/ -UseBasicParsing

    何をするコマンドか。 実行場所は、PowerShell です。 Invoke-WebRequest は、URL へ要求を送ります。 -Uri は、その URL です。 59999 は、この教科書で公開していないポートです。 -UseBasicParsing は、手順の取得コマンドと同じスイッチです。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。

    出力が違うとき。 ページの中身が表示されたら、59999 番を本当に使っているプログラムがあります。番号を変えて、使っていないポートで試してください。

    1. 開いていないポートへ接続します。
    curl -sS -D - http://127.0.0.1:59999/

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 オプションは、成功した取得のときと同じです。ポートだけを 59999 にしています。この章では、この番号を公開していません。

    期待する出力。

    curl: (7) Failed to connect to 127.0.0.1 port 59999 after 0 ms: Couldn't connect to server

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 7 でした。

    出力が違うとき。 こんにちは と出たら、59999 番ではなく 8000 番へ送っています。URL のポートを確認してください。

    Linux で確認できた1行は、こう読みます。curl: (7) の左がコマンド、括弧の中が curl の失敗番号です。Failed to connect は、接続できなかった、という意味です。port 59999 が、開こうとしたポートです。Couldn't connect to server は、そこに待っているプログラムが無い、という意味です。

    確認テスト

    文章で答えてください。新しいコマンドを実行しなくても答えられます。

    問題1

    0.0.0.0:8000->8000/tcp の矢印の左右は、何ですか。

    解答と解説

    左が自分のパソコンの 8000 番、右がコンテナの 8000 番です。

    --publish 8000:8000 の結果として、この形が docker ps に出ました。左へ送ると、右のアプリに届きます。

    問題2

    memo-net-a へ、なぜ IP アドレスを書かずに接続できましたか。

    解答と解説

    同じユーザー定義ネットワークにいて、コンテナ名で通信できるからです。

    公式の説明では、自分で作ったネットワークではコンテナ名が使えます。既定の bridge では、名前では呼べません。

    問題3

    第6章の 8000/tcp と、この章の矢印付きの表示は、何が違いますか。

    解答と解説

    第6章は EXPOSE のメモだけで、この章はポート公開です。

    メモだけでは、自分のパソコンの 8000 番からは開けません。--publish を付けたとき、矢印が出ます。

    まとめ

    • ポート: 1台のパソコンの中で、待っているプログラムを区別する番号です。
    • ポート公開: コンテナのポートを、自分のパソコンのポートへつなぐことです。--publish がそれを行います。
    • ユーザー定義ネットワーク: 自分で作った、コンテナ同士が名前で通信できるネットワークです。

    片付け

    公開したコンテナ、ネットワーク内のコンテナ、ネットワークの順に消します。イメージ memo:ch06 は残します。

    1. 2つのコンテナを止めます。
    docker stop memo-ch07 memo-net-a

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker stop は、コンテナを止めます。引数は、止める名前を2つ続けています。オプションは付けていません。アプリは約10秒待ってから止まることがあります。

    期待する出力。

    memo-ch07
memo-net-a

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。行の順は違ってよいです。

    出力が違うとき。 片方だけ No such container なら、その名前は既にありません。残っている名前だけを止めてください。

    1. 止めたコンテナを消します。
    docker rm memo-ch07 memo-net-a

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker rm は、コンテナを消します。2つの名前を続けています。オプションは付けていません。取得用の短いコンテナは --rm で既に消えています。

    期待する出力。

    memo-ch07
memo-net-a

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 動いている旨なら、手順1が終わっていません。docker stop のあと、もう一度消してください。

    1. ネットワークを消します。
    docker network rm memo-net

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker network rm は、ネットワークを消します。引数は、memo-net です。オプションは付けていません。繋がっているコンテナがあると、消せません。

    期待する出力。

    memo-net

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 使用中という旨なら、そのネットワークのコンテナが残っています。docker ps -a で名前を見て、docker rm してから、もう一度消してください。not found なら、既にありません。
