    第2部 Docker

    第8章 データを残す

    目安は約45分です。

    確認したバージョン

    2026-10-16 に、次を確認しました。

    • Volumes
    • Docker Engine 29.9.1 の docker volume create --help と docker run --help
    • New-Item
    • GNU coreutils 9.4 の od --help

    busybox:1.37.0 を使います。公式の説明では、ボリュームは Docker が管理し、コンテナを消しても中身は残ります。バインドマウントは、ホストのディレクトリ構成と OS に依存します。--mount は、--volume より明示的なので、こちらを使います。source は元、target はコンテナの中のパスです。

    この章のゴール

    • コンテナを消しても残るボリュームへ、文字を書いて読み戻せる
    • ホストのディレクトリを、バインドマウントでコンテナから読める
    • Linux の改行が、バイト 0a だと説明できる

    前提

    第4章で、--rm を付けるとコンテナが消えることを見ました。消えるのはコンテナです。この章は、その外側にデータを置く話です。

    実行場所は、Ubuntu の端末です。Windows では、ボリュームの手順は WSL2 の Ubuntu で実行します。バインドマウントのパスだけ、OSで違います。

    たとえ話

    学校のロッカーと、自分の机の引き出しを想像してください。

    ロッカーは学校が管理します。下校しても中身は残ります。これがボリュームです。自分の机の引き出しを、そのまま教室へ持っていくのが、バインドマウントです。

    手を動かす

    最初は、Docker が管理するボリュームです。コマンドは OS で同じです。

    1. 名前付きボリュームを作ります。
    docker volume create memo-data

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker volume create は、ボリュームを作ります。引数の memo-data は、その名前です。オプションは付けていません。ボリュームは、Docker がホスト上のディレクトリとして持ち、コンテナへマウントできる保存場所です。マウントは、外の保存場所を、コンテナの中のパスへつなぐことです。

    期待する出力。

    memo-data

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 既にある旨なら、前の実験が残っています。片付けの docker volume rm memo-data を実行してから、もう一度作ってください。

    1. ボリュームへ1行書きます。
    docker run --rm --mount type=volume,source=memo-data,target=/data busybox:1.37.0 sh -c 'printf "%s\n" "残るメモ" > /data/memo.txt'

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker run は、コンテナを起動します。 --rm は、終了したコンテナを消します。 --mount は、保存場所をコンテナへつなぐオプションです。 type=volume は、ボリュームであることを指定します。 source=memo-data は、手順1の名前です。 target=/data は、コンテナの中でのパスです。 busybox:1.37.0 は、イメージです。 sh -c は、その後ろの文字列をシェルのコマンドとして実行します。 printf は、残るメモ と改行を出します。 > は、その出力を /data/memo.txt へ書きます。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。コンテナは --rm で消えています。ファイルはボリュームに残ります。

    出力が違うとき。 ボリュームが無い旨なら、手順1が終わっていません。残るメモ が画面に出たら、> 以降がコンテナの中のコマンドに入っていません。引用符を含めてコピーし直してください。

    1. 新しいコンテナから、同じファイルを読みます。
    docker run --rm --mount type=volume,source=memo-data,target=/data busybox:1.37.0 cat /data/memo.txt

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 コンテナは手順2とは別の、新しいコンテナです。 --rm は、終了後に消します。 --mount の source と target は、手順2と同じボリュームとパスです。 cat /data/memo.txt は、そのファイルを表示します。イメージの CMD の代わりに、cat を実行します。

    期待する出力。

    残るメモ

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。コンテナを消しても、ボリュームの中身は残っています。

    出力が違うとき。 ファイルが無い旨なら、手順2の書き込み先が /data/memo.txt ではありません。手順2からやり直してください。

    次は、ホストのディレクトリをコンテナから見ます。パスの形が OS で違います。

    実行場所は、PowerShell です。Docker Desktop が、Windows のパスをコンテナへ渡します。この手順は未確認です。普段の作業ファイルは、第2章のとおり WSL2 の Ubuntu 側に置きます。ここは、パスの形の違いを見るための手順です。

    1. ディレクトリを作ります。
    New-Item -ItemType Directory -Force -Path "$HOME\docker-learn\ch08"

    何をするコマンドか。 実行場所は、PowerShell です。 New-Item は、ファイルやディレクトリを作ります。 -ItemType Directory は、ファイルシステムではディレクトリを作る指定です。Microsoft Learn の New-Item に、FileSystem では Directory が選べると書いてあります。 -Force は、読み取り専用の既存項目を上書きして作る指定です。同じページには、実装はプロバイダによって違う、とも書いてあります。 -Path は、作る場所です。 $HOME は、Windows の利用者フォルダです。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。

    出力が違うとき。 アクセスを拒否された旨なら、そのフォルダへ書く権限がありません。$HOME\docker-learn\ch08 のままもう一度実行してください。

    1. 1行のファイルを作ります。
    Set-Content -Path "$HOME\docker-learn\ch08\note.txt" -Value "ホストのファイル" -Encoding utf8

    何をするコマンドか。 実行場所は、PowerShell です。 Set-Content は、ファイルへ文字を書きます。 -Path は、ファイルの場所です。 -Value は、書く文字です。 -Encoding utf8 は、文字の符号化です。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。

    出力が違うとき。 ディレクトリが無い旨なら、手順1が終わっていません。

    1. そのディレクトリを、コンテナから読みます。
    docker run --rm --mount "type=bind,source=$HOME\docker-learn\ch08,target=/data" busybox:1.37.0 cat /data/note.txt

    何をするコマンドか。 実行場所は、PowerShell です。 docker run は、コンテナを起動します。 --rm は、終了後に消します。 --mount は、保存場所をつなぎます。 type=bind は、ホストのパスをそのままつなぐ指定です。 source は、Windows のディレクトリです。 target=/data は、コンテナの中のパスです。 cat /data/note.txt は、その中のファイルを表示します。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。

    出力が違うとき。 パスが無い旨なら、source のフォルダがありません。手順1のパスと揃えてください。バックスラッシュが消えるときは、コマンド全体を引用符ごとコピーしてください。

    1. ファイルのバイトを表示します。
    Format-Hex -Path "$HOME\docker-learn\ch08\note.txt"

    何をするコマンドか。 実行場所は、PowerShell です。 Format-Hex は、ファイルのバイトを16進数で表示します。 -Path は、そのファイルです。Windows の改行は、0D のあとに 0A が続くことが多いです。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。Linux で同じ文字を改行付きで書いたバイトは、下の Linux タブにあります。

    出力が違うとき。 コマンドが見つからない旨なら、PowerShell ではありません。

    実行場所は、Ubuntu の端末です。

    1. ディレクトリを作ります。
    mkdir -p "$HOME/docker-learn/ch08"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 mkdir -p は、ディレクトリを作ります。既にあってもエラーにしません。場所は、ホームの中の docker-learn/ch08 です。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

    出力が違うとき。 Permission denied なら、ホーム以外へ作ろうとしています。コマンドをコピーし直してください。

    1. 1行のファイルを作ります。
    printf '%s\n' 'ホストのファイル' > "$HOME/docker-learn/ch08/note.txt"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 printf は、書式どおりに文字を出します。 '%s\n' の \n は改行です。 > は、出力をファイルへ書きます。このファイルは、Ubuntu のディスク上にあります。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

    出力が違うとき。 文字が画面に出たら、> が抜けています。コマンドをコピーし直してください。

    1. そのディレクトリを、コンテナから読みます。
    docker run --rm --mount type=bind,source="$HOME/docker-learn/ch08",target=/data busybox:1.37.0 cat /data/note.txt

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker run は、コンテナを起動します。 --rm は、終了後に消します。 --mount は、保存場所をつなぎます。 type=bind は、ホストのパスをそのままつなぐ指定です。 source は、手順1のディレクトリです。 target=/data は、コンテナの中のパスです。 cat /data/note.txt は、ホストに書いたファイルを、コンテナの中のパスとして表示します。

    期待する出力。

    ホストのファイル

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。コンテナの中にファイルをコピーしたのではありません。ホストのディレクトリを、そのまま見ています。

    出力が違うとき。 パスが無い旨なら、source のディレクトリがありません。手順1からやり直してください。/mnt/c で始まるパスは、Windows 側のディスクです。この教科書では使いません。

    1. 改行のバイトを表示します。
    od -An -tx1 "$HOME/docker-learn/ch08/note.txt"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 od は、ファイルのバイトを表示します。 -A は、先頭に出す位置の基数です。 n は、位置を出さない、という指定です。この環境の od --help には、RADIX が doxn のどれかで、n は None とあります。 -t は、表示形式です。 x1 は、1バイトずつ16進数で出す指定です。

    期待する出力。

     e3 83 9b e3 82 b9 e3 83 88 e3 81 ae e3 83 95 e3
 82 a1 e3 82 a4 e3 83 ab 0a

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。最後の 0a が、改行の1バイトです。その前に 0d はありません。Linux のこのファイルの改行は、0a だけです。

    出力が違うとき。 最後が 0d 0a なら、Windows の改行が入っています。手順2の printf で作り直してください。ファイルが無い旨なら、手順2が終わっていません。

    何が起きたか

    手順2のコンテナは --rm で消えました。手順3の新しいコンテナが、同じ memo-data から 残るメモ を読めました。公式の説明どおり、ボリュームの中身はコンテナの寿命の外にあります。

    バインドマウントは、ホストの ch08 をコンテナの /data として見せました。コピーではありません。だから、ホストで書いた文字が、コンテナの cat に出ました。パスは OS の形のまま渡します。WSL2 では、作業ファイルを Linux 側に置きます。/mnt/c は、Windows のディスクを Linux から見た場所で、この教科書の作業場所にはしません。

    左は、コンテナが消えても名前付きの保存場所が残ります。右は、ホストのディレクトリそのものを見ます。

    壊してみる

    存在しないパスをバインドマウントして、エラーを読みます。

    1. 無いディレクトリをマウントします。
    docker run --rm --mount "type=bind,source=$HOME\docker-learn\ch08\missing,target=/data" busybox:1.37.0 ls /data

    何をするコマンドか。 実行場所は、PowerShell です。 --mount の type=bind は、ホストのパスをそのままつなぎます。 source は、わざと作っていない missing です。 target=/data は、コンテナの中のパスです。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。Linux で同じ種類の失敗をさせた出力は、下の Linux タブにあります。

    出力が違うとき。 ls の一覧が出たら、missing が本当にあります。名前を確認してください。

    1. 無いディレクトリをマウントします。
    docker run --rm --mount type=bind,source="$HOME/docker-learn/ch08/missing",target=/data busybox:1.37.0 ls /data

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 --mount の type=bind は、ホストのパスをそのままつなぎます。 source は、わざと作っていない missing です。 target=/data は、コンテナの中のパスです。 ls /data は、つながった先を見ようとするコマンドです。この実行では、コンテナが起動する前に拒否されました。

    期待する出力。

    docker: Error response from daemon: invalid mount config for type "bind": bind source path does not exist: /home/ubuntu/docker-learn/ch08/missing

Run 'docker run --help' for more information

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 125 でした。/home/ubuntu の部分は、自分のホームのパスに変わります。

    出力が違うとき。 一覧が出たら、missing というディレクトリが本当にあります。rm -r で消してから、もう一度実行してください。自分で作ったものであることを確認してから消します。

    invalid mount config for type "bind" は、バインドマウントの指定が成立しない、という意味です。bind source path does not exist は、元のパスが無い、という意味です。コロンの右が、探したパスです。ボリュームと違い、--mount type=bind は、無いパスを勝手に作りません。

    確認テスト

    文章で答えてください。新しいコマンドを実行しなくても答えられます。

    問題1

    手順2のコンテナを消したあとに、残るメモ が読めたのはなぜですか。

    解答と解説

    文字がコンテナではなく、ボリューム memo-data に書いてあったからです。

    --rm が消すのはコンテナです。同じボリュームを次のコンテナへマウントすると、ファイルが残っています。

    問題2

    バインドマウントで、コンテナはファイルのコピーを持っていますか。

    解答と解説

    持っていません。ホストのディレクトリを、そのまま見ています。

    source のディレクトリと、コンテナの target は、同じ場所です。ホストで書いた文字が、コンテナの cat に出ました。

    問題3

    この章の Linux の note.txt の最後のバイト 0a は何ですか。

    解答と解説

    改行です。

    printf の \n が、この1バイトになりました。0d は付いていません。

    まとめ

    • ボリューム: Docker が管理する保存場所です。コンテナを消しても、中身は残ります。
    • バインドマウント: ホストのパスを、コンテナの中のパスとしてそのまま見せることです。
    • マウント: 外の保存場所を、コンテナの中のパスへつなぐことです。

    片付け

    ボリュームを消します。バインドマウントに使ったディレクトリも消します。

    1. ボリュームを消します。
    docker volume rm memo-data

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 docker volume rm は、ボリュームを消します。引数は、memo-data です。オプションは付けていません。中のファイルも消えます。使用中のボリュームは消せません。この章のコンテナは --rm で終わっているので、使用中ではありません。

    期待する出力。

    memo-data

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 使用中という旨なら、そのボリュームをマウントしたコンテナが残っています。docker ps -a で見て、docker rm してから、もう一度消してください。no such volume なら、既にありません。

    ディレクトリの消し方は、作った場所に合わせます。

    1. Windows 側に作ったディレクトリを消します。
    Remove-Item -Recurse -Force -Path "$HOME\docker-learn\ch08"

    何をするコマンドか。 実行場所は、PowerShell です。 Remove-Item は、ファイルやディレクトリを消します。 -Recurse は、中も消す指定です。 -Force は、確認なしで消す指定です。 -Path は、消す場所です。WSL2 側のファイルは消しません。

    期待する出力。

    未確認。この執筆環境は Linux で、PowerShell を実行できませんでした。

    出力が違うとき。 パスが無い旨なら、既にありません。次の章へ進んでよいです。

    1. 練習ディレクトリを消します。
    rm -r "$HOME/docker-learn/ch08"

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 rm -r は、ディレクトリの中も含めて消します。消すのは ch08 だけです。docker-learn 自体は残します。

    期待する出力。

    何も表示されません。2026-10-16 にこの執筆環境で実行し、終了ステータスは 0 でした。

    出力が違うとき。 ディレクトリが無い旨なら、既に消えています。そのままで次の章へ進んでよいです。
