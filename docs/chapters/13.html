    第13章 Pod

    目安は約40分です。

    確認したバージョン

    2026-10-16 に、次を確認しました。

    • Pods
    • このクラスタの kubectl explain pod.spec.containers.imagePullPolicy
    • kubectl options の --context と -n
    • kubectl apply --help、kubectl get --help、kubectl wait --help、kubectl logs --help、kubectl delete --help
    • kind v0.33.0 の kind load docker-image --help

    クラスタは、第12章で作った memo です。コンテキストは kind-memo です。

    この章のゴール

    • 自作のイメージを、kind のノードへ載せることができる
    • マニフェスト から Pod を1つ作り、Running になるまで待てる
    • 名前空間 の中だけを見て、作った Pod を消すことができる

    前提

    第6章のイメージの作り方と、第12章のクラスタを使います。クラスタ名は memo です。kubectl には、毎回 --context kind-memo を付けます。

    実行場所は、Ubuntu の端末です。Windows では、WSL2 の Ubuntu です。この章のコマンドは、どちらも同じです。

    ラベル は、リソースに付ける名前と値の印です。あとから、その印で選びます。この章では app: memo を付けます。

    たとえ話

    1人用の机を想像してください。

    机の上に、アプリの入った箱を1つ置きます。その机が Pod です。部屋の名前が名前空間です。机の置き方を書いた紙が、マニフェストです。

    1. アプリを作ります。
    cat > app.py <<'EOF'
import os
from http.server import BaseHTTPRequestHandler, HTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        message = os.environ.get("APP_MESSAGE", "podから")
        body = message.encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)


def main():
    port = int(os.environ.get("PORT", "8000"))
    server = HTTPServer(("0.0.0.0", port), Handler)
    print(f"listening on {port}", flush=True)
    server.serve_forever()


if __name__ == "__main__":
    main()
EOF

    何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは $HOME/docker-learn/ch13 です。第6章と同じ、ファイルを作る書き方です。返る文字の初期値は podから です。APP_MESSAGE という 環境変数 があれば、その文字を返します。同じファイルを samples/ch13/app.py に置いてあります。

    1. Pod のマニフェストを作ります。

kind: Pod
metadata:
  name: memo
  namespace: memo
  labels:
    app: memo
spec:
  containers:
  - name: web
    image: memo:ch13
    imagePullPolicy: IfNotPresent
    ports:
    - containerPort: 8000
EOF

    何をするコマンドか。 実行場所は、Ubuntu の端末です。カレントディレクトリは $HOME/docker-learn/ch13 です。同じファイルを samples/ch13/pod.yaml に置いてあります。

    apiVersion: v1 と kind: Pod は、これが Pod の定義だと API に伝えます。 metadata.name は、Pod の名前 memo です。 metadata.namespace は、入れる名前空間です。 labels の app: memo は、ラベルです。 containers は、Pod の中で動かすコンテナの一覧です。公式の Pod の説明では、Pod は作って管理できる計算の最小単位です。 image: memo:ch13 は、手順4のイメージです。 imagePullPolicy: IfNotPresent は、このクラスタの kubectl explain では、ディスクにイメージが無いときだけ取得します。 :latest を付けないので、既定も IfNotPresent ですが、明示しています。 containerPort: 8000 は、コンテナが待つポートの宣言です。これだけでは、自分のパソコンへは公開しません。

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 kubectl get は、リソースの一覧を出します。 pod memo は、Pod の名前です。 --namespace は、kubectl options では、この操作の名前空間です。短い書き方は -n です。このコマンドは、長い書き方を使います。 --context は、接続先です。

    1. Running になるまで待ちます。

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 kubectl wait は、条件を満たすまで待ちます。 --for=condition=Ready は、help の例にある、Ready になるまで待つ指定です。 pod/memo は、種類と名前です。 --timeout=60s は、help の例では、待つ上限です。 60s は 60 秒です。

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 timed out なら、60 秒で Ready になりませんでした。kubectl get pod memo --namespace memo --context kind-memo で STATUS を見てください。 ImagePullBackOff なら、イメージがノードにありません。

    1. 載ったノードを見ます。

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 -o wide は、kubectl get --help の例では、ノード名などの列を足す指定です。

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 kubectl logs は、コンテナのログのスナップショットを出します。引数は Pod の名前です。コンテナが1つなら、コンテナ名は要りません。

    何が起きたか

    マニフェストを apply すると、API サーバーが Pod を記録します。スケジューラがノードを選び、そのノードの kubelet がコンテナを起動します。この実行では、選ばれたノードは memo-worker でした。

    左の紙がマニフェストです。右のノードの中で、Pod が1つ動きます。自分のパソコンの 8000 番へは、まだつながっていません。

    確認テスト

    文章で答えてください。新しいコマンドを実行しなくても答えられます。

    問題1

    Pod は、Kubernetes では何の単位ですか。

    解答と解説

    作って管理できる計算の最小単位です。

    公式の Pod の説明では、そう書かれています。この章では、その中にコンテナを1つ入れました。

    問題2

    imagePullPolicy: IfNotPresent は、何をしますか。

    解答と解説

    ノードのディスクにイメージが無いときだけ、取得します。

    このクラスタの explain では、その意味です。先に kind load したので、外のレジストリへ取りにいきません。

    問題3

    この Pod を、名前空間 memo の外の一覧に出すには、何が要りますか。

    解答と解説

    --namespace memo か、-n memo です。

    名前空間を指定しない get は、今の名前空間だけを見ます。この Pod の metadata.namespace は memo です。

    まとめ

    • Pod: Kubernetes で作って管理できる、計算の最小単位です。1つ以上のコンテナが、同じノードで動きます。
    • 名前空間: リソースの名前を分ける部屋です。この章の Pod は memo に入っています。
    • マニフェスト: 望ましい状態を YAML で書いたファイルです。kubectl apply -f が、それをクラスタへ反映します。
    • ラベル: リソースに付ける、名前と値の印です。この章では app: memo です。

    片付け

    名前空間とイメージは残します。第14章で使います。Pod だけ消します。

    1. Pod を消します。
    kubectl delete -f "$HOME/docker-learn/ch13/pod.yaml" --context kind-memo

    何をするコマンドか。 実行場所は、Ubuntu の端末です。 kubectl delete は、リソースを消します。 -f は、kubectl delete --help の例では、ファイル名です。ファイルに書いた Pod を消します。名前空間 memo は、ファイルの対象ではないので残ります。

    期待する出力。

    pod "memo" deleted from memo namespace

    この出力は、2026-10-16 にこの執筆環境で実行した結果です。終了ステータスは 0 でした。

    出力が違うとき。 NotFound なら、すでに消えています。次の章へ進んでください。
