    用語集

    各章のまとめで説明した用語です。本文のリンクからも開けます。

    コンテナ

    アプリと、それを動かすのに必要なファイルが、今のOSの上で動いている実体です。

    第1章 コンテナとは何か

    仮想マシン

    アプリのために、別のカーネルを持つ別のOSを動かす仕組みです。

    第1章 コンテナとは何か

    イメージ

    コンテナを動かすためのファイルと設定を、一つに束ねたものです。

    第1章 コンテナとは何か

    カーネル

    OSの中心で、アプリとコンピュータ本体の仲立ちをする部分です。

    第1章 コンテナとは何か

    Docker Engine

    Linux 上でコンテナを動かす本体です。`docker` コマンドは、ここへ頼みごとを送ります。

    第2章 環境を整える

    Docker Desktop

    Windows で Docker を使うためのアプリです。標準では WSL2 の上で Engine を動かします。

    第2章 環境を整える

    WSL2

    Windows の中で Linux を動かす仕組みです。この教科書の Windows 側の実行場所は、その中の Ubuntu です。

    第2章 環境を整える

    dockerグループ

    `docker` コマンドを、sudo なしで実行できるようにする利用者の集まりです。

    第2章 環境を整える

    カレントディレクトリ

    端末が今いるディレクトリです。相対パスは、ここから探します。

    第3章 コマンドラインの基礎

    パス

    ファイルやディレクトリの場所を書いた名前です。先頭が / なら絶対パス、そうでなければ相対パスです。

    第3章 コマンドラインの基礎

    標準出力

    コマンドが結果を流す、画面へ向かう出力の通り道です。

    第3章 コマンドラインの基礎

    リダイレクト

    `>` で、標準出力の行き先をファイルへ変える書き方です。

    第3章 コマンドラインの基礎

    終了ステータス

    コマンドが終わったときの成功と失敗の番号です。成功は 0 で、失敗は 0 以外です。

    第3章 コマンドラインの基礎

    デタッチ

    コンテナを裏で動かし、端末へはコンテナIDだけを返す起動の仕方です。

    第4章 はじめてのコンテナ

    コンテナ名

    `--name` で自分が見分けのために付ける名前です。

    第4章 はじめてのコンテナ

    コンテナID

    Docker がコンテナに付ける識別子です。一覧では先頭の12文字だけが表示されます。

    第4章 はじめてのコンテナ

    レイヤー

    イメージを構成する、ファイルの変更一枚ずつの段です。履歴の1行が、その段に対応します。

    第5章 イメージとレイヤー

    タグ

    イメージにつけるラベルです。`名前:タグ` の、コロンの右側です。

    第5章 イメージとレイヤー

    レジストリ

    イメージを置いて配る場所です。標準では Docker Hub の `docker.io` を使います。

    第5章 イメージとレイヤー

    Dockerfile

    イメージの材料と手順を書いたファイルです。ビルドは、このファイルを標準で読みます。

    第6章 Dockerfileで自作イメージを作る

    ビルド

    Dockerfile に従って、イメージを作る作業です。`docker build` がそれを行います。

    第6章 Dockerfileで自作イメージを作る

    ベースイメージ

    FROM で指定する、自分のファイルを乗せる前の土台です。

    第6章 Dockerfileで自作イメージを作る

    ポート

    1台のパソコンの中で、待っているプログラムを区別する番号です。

    第7章 ポートとネットワーク

    ポート公開

    コンテナのポートを、自分のパソコンのポートへつなぐことです。`--publish` がそれを行います。

    第7章 ポートとネットワーク

    ユーザー定義ネットワーク

    自分で作った、コンテナ同士が名前で通信できるネットワークです。

    第7章 ポートとネットワーク

    ボリューム

    Docker が管理する保存場所です。コンテナを消しても、中身は残ります。

    第8章 データを残す

    バインドマウント

    ホストのパスを、コンテナの中のパスとしてそのまま見せることです。

    第8章 データを残す

    マウント

    外の保存場所を、コンテナの中のパスへつなぐことです。

    第8章 データを残す

    Compose

    複数のコンテナの構成を1つのファイルに書き、まとめて起動する仕組みです。

    第9章 Docker Compose

    サービス

    Compose のファイルの中の、1種類のコンテナです。名前が、ネットワークの宛先になります。

    第9章 Docker Compose

    環境変数

    プログラムの外から渡す、名前付きの値です。接続先やパスワードを、コードに直接書きません。

    第9章 Docker Compose

    マルチステージビルド

    Dockerfile に FROM を2回以上書き、必要なファイルだけを後のステージへコピーするビルドです。

    第10章 イメージを小さく安全にする

    ビルドステージ

    FROM で始まり、次の FROM の手前まで続く、ビルドの1区切りです。

    第10章 イメージを小さく安全にする

    非rootユーザー

    root ではない利用者です。コンテナのプロセスは、この利用者の権限で動きます。

    第10章 イメージを小さく安全にする

    Kubernetes

    コンテナで動くアプリを、宣言した望ましい状態へ寄せ続ける仕組みです。

    第11章 Kubernetesとは何か、なぜ必要か

    クラスタ

    コントロールプレーンと、1台以上のノードをまとめたものです。

    第11章 Kubernetesとは何か、なぜ必要か

    望ましい状態

    こうあってほしい、と書いた結果です。今の状態が違えば、Kubernetes がそこへ寄せます。

    第11章 Kubernetesとは何か、なぜ必要か

    kind

    Docker のコンテナをノードにして、手元に Kubernetes のクラスタを作る道具です。

    第12章 ローカル環境を作る

    ノード

    Pod を動かす場所です。この章の kind では、ノード1台がコンテナ1つです。

    第12章 ローカル環境を作る

    kubeconfig

    kubectl がクラスタへ接続するための設定ファイルです。既定の場所は `$HOME/.kube/config` です。

    第12章 ローカル環境を作る

    Pod

    Kubernetes で作って管理できる、計算の最小単位です。1つ以上のコンテナが、同じノードで動きます。

    第13章 Pod

    名前空間

    リソースの名前を分ける部屋です。この章の Pod は `memo` に入っています。

    第13章 Pod

    マニフェスト

    望ましい状態を YAML で書いたファイルです。`kubectl apply -f` が、それをクラスタへ反映します。

    第13章 Pod

    ラベル

    リソースに付ける、名前と値の印です。この章では `app: memo` です。

    第13章 Pod

    Deployment

    Pod と ReplicaSet の望ましい状態を宣言し、制御された速さでそこへ寄せるリソースです。

    第14章 Deploymentで複数台にする、更新する、ロールバックする

    レプリカ

    同じ Pod の定義を、同時に動かしたい数です。`spec.replicas` に書きます。

    第14章 Deploymentで複数台にする、更新する、ロールバックする

    ロールバック

    Deployment を、前のリビジョンの定義へ戻す操作です。`kubectl rollout undo` がそれを行います。

    第14章 Deploymentで複数台にする、更新する、ロールバックする

    ReplicaSet

    指定した数の Pod を保つリソースです。Deployment がこれを作り、直接は管理しません。

    第14章 Deploymentで複数台にする、更新する、ロールバックする

    Service

    ラベルが一致する Pod へ、安定した入口から通信を届けるリソースです。Pod が入れ替わっても、入口の名前は残ります。

    第15章 Serviceで公開する

    NodePort

    Service の公開の型の1つです。各ノードの同じポート番号でも、Pod へ届くようにします。

    第15章 Serviceで公開する

    セレクタ

    Service が、どの Pod へ届けるかを選ぶラベルの組です。この章では `app: memo` です。

    第15章 Serviceで公開する
